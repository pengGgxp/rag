# 后台支付设置

## 两步充值与统一收银台

- 管理员在“充值与付款方式”维护全站档位、自定义开关、整数积分/元；固定档位金额与积分不受自定义比例影响。付款方式的稳定 ID、展示名称、启停、渠道与网关编码在同一处管理，不按名称自动合并，不自动路由或转单。
- 支付 FM / 易支付页只管理商户凭据、启停与官网入口。原 `site_payment_configs` 中的报价及方式字段保留历史快照，不再参与已建立的站点统一配置。定价助手从当前可充值的统一档位读取参考套餐。
- `GET /payments/catalog` 返回 `enabled`、`packages` 和可选 `custom`，不公开技术渠道。`POST /payments/checkout-preview` 接受 `package_id`、`quote`、可选整元 `custom_amount_fen`，返回服务端金额、积分及 `{id,label}` 付款方式；它不会创建订单。
- `POST /payments/orders` 在上述选择基础上接受 `payment_method_id`、`idempotency_key`，由服务端决定渠道、网关编码和到账积分。报价过期、方式停用返回 409；额外伪造金额、积分和渠道字段被拒绝。
- `GET /payments/order-attempts/{key}` 只查询当前用户及工作区下的原订单，未创建返回 null；不调用网关。浏览器在发送前将请求键保存在收银台 URL，刷新或网络异常先查询原请求。提交原请求返回原订单，不自动重试网关调用。
- 新订单固定统一配置版本、报价、付款方式 ID/名称，以及原有渠道配置版本和网关编码。支付网关返回 `/payments/checkout?order={id}`；前端仅查询真实状态，不能凭返回参数发积分。旧订单仍使用原渠道配置版本（或既有环境配置）验签。
- `GET/PUT /site/admin/payments/recharge` 只向站点管理员开放，采用递增版本及 409 冲突保护。公开付款方式不含密钥；渠道密钥仍使用既有加密和审计脱敏。

### 0051 迁移与恢复

`0051_recharge_checkout` 从每个渠道最新版本中选取启用配置；优先原样采用易支付报价，仅迁移启用渠道的方式。多个启用渠道报价不一致时，在建表前中止，需先确认报价并停用非迁移来源渠道后重新执行。不修改订单、余额或历史账单。

没有任何数据库渠道配置的全新环境显示环境草稿，第一次保存统一配置后以数据库为准。只有停用渠道时保留报价草稿但不开放付款方式。

部署必须先备份、执行 `alembic upgrade head` 再更新 API/Web；本任务不部署线上。回退代码前可回退 0051，但会丢失新站点配置，必须先导出该配置；渠道历史版本和原订单金额、积分不会改写。真实商户付款及回调仍须另行验收。

## 配置来源

- 首次读取且尚无后台版本时，当前 `ZHIFUX_*` 与 `RECHARGE_PACKAGES_JSON` 环境变量以草稿方式呈现，商户密钥不返回浏览器。
- 易支付可从 `EZFP_ENABLED`、`EZFP_PID`、`EZFP_PAY_TYPE`、`EZFP_PRIVATE_KEY`、`EZFP_PUBLIC_KEY`、`EZFP_RECHARGE_PACKAGES_JSON` 导入草稿。下单固定使用官方 `https://www.ezfp.cn/api/pay/create`；商户私钥和平台公钥来自不同主体，分别校验 RSA 格式，不要求属于同一密钥对。
- 管理员首次保存后，数据库中的版本化配置成为充值目录及新订单的权威来源。之后的环境变量变更不会覆盖后台设置。
- 每张订单记录渠道类型及配置版本。密钥轮换后，旧订单回调仍按订单版本验签；更改渠道不会改写已创建订单金额、积分或历史充值记录。
- 尚未绑定配置版本的历史订单继续使用服务端原有环境配置验签。迁移时应在处理完这类历史待处理订单前保留原商户配置。

## 密钥与启用

商户密钥使用 API 服务配置的 `SITE_CONFIG_ENCRYPTION_KEY` 加密后入库。该密钥由运维配置，不由管理页面设置；同一部署中的 API 实例必须使用一致值。丢失该密钥将无法解密已保存凭据，数据库备份也必须单独保护该密钥。

后台只返回密钥是否存在。密钥输入留空表示保留现有密钥，清除需要确认。加密密钥不可用或支付配置不完整时不能开放充值。支付网关、API 公网地址及网站返回地址均应使用可访问的 HTTPS 地址；后台展示回调地址供商户侧配置。

## 充值档位

每档包括稳定 ID、展示名称、人民币金额（保存为整数分）和到账积分。ID 必须唯一，最多 20 档；启用时至少需要一档。用户充值目录只展示该渠道后台配置的档位，服务端不再自动补入 20、50、100、200 元选项；调整档位后，目录即时使用已保存的配置，旧订单仍按下单时锁定的金额和积分处理。

“允许用户自定义充值金额”按渠道独立设置，默认关闭。管理员同时设置整数积分/元比例，默认每元 100 积分；用户输入仅接受整元，服务端负责计算并限制单笔最多 1,000,000 积分。比例仅作用于自定义充值，固定档位的金额与积分不受影响。关闭后目录不再提供该选项，服务端也拒绝伪造或旧页面提交的自定义金额。无论开关、比例或方式后续如何修改，已创建订单均保留其金额、积分、渠道、付款方式和支付配置版本，回调按创建时的渠道配置校验。自定义充值的报价由服务端生成并校验。

价格助手使用当前生效配置的档位作保守换算基准；没有有效档位时会返回不可用状态。

## 接口

- `GET /site/admin/payments`：读取当前有效配置或环境变量草稿；不返回密钥正文。
- `PUT /site/admin/payments`：携带版本号保存配置。版本不匹配返回 `409`，客户端应保留输入并要求管理员明确放弃后重新加载。
- `GET/PUT /site/admin/payments/{provider_key}`：分别读取或保存 `zhifux`、`ezfp` 渠道。配置版本全局唯一，冲突检查按渠道执行；订单绑定创建时的渠道版本。
- 易支付接收 `/payments/ezfp/notify`，支付 FM 继续使用 `/payments/zhifux/notify`。易支付以 RSA-SHA256 验签，校验商户、金额、订单、支付方式和成功状态后才入账。
- 普通用户端继续使用 `/payments/catalog`、现有下单和回调接口；管理员页面不会直接发起真实付款。

修改、启停、档位及密钥的版本变化记录站点审计，只记录被修改字段和版本，不记录密钥。真实付款及公网回调仍需独立人工验收；页面保存成功不代表商户端支付链路已验证。
