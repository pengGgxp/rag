# 检索调试验收

对应 Issue #11。目标是让现有检索过程可观察，不修改召回数量、RRF 公式、
证据阈值或模型配置。

## 实现

- 新增检索调试视图，显示来源片段、原文定位、排名和向量距离。
- 回答的 TRACE 入口可查看已经持久化的检索记录。
- 新增 `POST /knowledge-bases/{id}/retrieval`，接收 `{ "query": "..." }`，
  返回 `trace` 和 `results`，空结果也有独立 trace。
- 保留原有 `/search` 的列表响应；问答共用相同检索实现，空结果回答不再根据相同问题反查最新 trace。
- 前端按知识库销毁并取消旧请求，支持手动取消、明确错误和重新提交。
- 片段只作为不可信纯文本展示，预览不加载文档中的外部媒体。

## 验证

- `npm run build`：通过。
- `docker compose run --rm --no-deps api python -m pytest -q`：15 项通过。
- 新增测试使用内存 SQLite，不接触本地知识库、对象存储或真实云端模型。
- 测试覆盖知识库隔离、删除及非就绪资料过滤、空结果独立 trace、参数校验、
  原接口兼容、向量故障回退和无证据拒答的 trace 对应关系。
- 对现有 6 个知识库执行真实云端混合检索，结果均只属于各自就绪文档，
  并验证返回 trace 与持久化记录一致，其中一个知识库返回 0 条结果。
- Playwright 检查检索、trace 展开、原文详情、接口失败及重试，
  并检查桌面和 `390x844` 移动视口。
- 取消请求回归通过，仅发送一次请求；知识库切换时的延迟响应不会回填到新知识库。
- 真实云端问答完成后，能够打开对应 trace；模拟 trace 接口错误后，界面重试恢复正常。
- `320x700` 窄屏和移动端 trace 对话框均未发现横向溢出。

## 边界

目前仍为已有的本地单工作空间运行方式。上述隔离验收指知识库数据过滤，
不代表已经实现用户身份、成员角色或多租户授权。
历史 trace 为检索当时的快照，不等于当前资料的实时状态。
本次未实现历史 trace 列表、检索参数调节或 reranker。
