# 文档处理任务验收记录

## 目标

让文档处理失败或排队时可被用户维护，并保留任务历史。

## 实现范围

- `POST /jobs/{id}/retry`：失败或取消任务创建新的排队任务。
- `POST /jobs/{id}/cancel`：取消排队或运行中的任务。
- 任务操作执行工作区和编辑权限检查。
- 取消后的 Worker 在解析和向量化关键节点重新检查任务状态。
- 文档列表展示任务错误原因，并提供重试/取消入口。
- 重试、取消写入操作审计日志。

## 状态规则

- `queued/running` 只能取消。
- `failed/cancelled` 可以重试。
- `succeeded` 不能重复重试或取消。
- 旧任务保留，不覆盖任务历史。

- 目标：修复大 PDF 将 114 段一次提交、超过上游每批 20 段限制的问题。

- 已有解析正文及段落的失败任务直接重试索引，保留段落 ID 和引用，不重新下载、解析或付费 OCR。
- 不修改价格、倍率、结算公式、开关或数据库结构；分批不产生额外平台计费事件，仍按本次索引总 Token 结算。
