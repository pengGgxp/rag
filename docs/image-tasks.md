# 图片任务、资源和积分

关联 Issue #75。对话提出图片生成或编辑需求后，模型只提供提示词、规格、数量与参考资源版本。
供应商、凭据、当前账号及工作区由服务端解析；默认模型和售价由站点管理员配置。

## 接口与能力

- 模型 `image_config` 明确选择 openai_images、gemini 或 responses 协议，生成/编辑开关、
  默认尺寸和质量、张数及参考图上限，以及每个操作/尺寸/质量的每张积分。
- Responses 配置中的模型名是主对话模型，另用 `image_model` 明确指定图片工具模型。
  Gemini 的尺寸/质量字段分别映射 aspectRatio/imageSize；不自动翻译或更换规格。
- `GET/PUT /site/admin/image-models` 管理默认模型并校验配置版本；生成/编辑可以分别关闭。
- `POST /image-tasks` 创建任务，幂等键为 UUID；`GET /image-tasks/{id}` 返回状态和资源。
  cancel 只停止未开始工作或标记取消；retry-save 仅重试资源交付，不再调用上游生成。
- 内置工具为 generate_image、edit_image、get_image_task。当前对话不支持工具或后台未配置时不注入。
  相同运行请求和参数通过持久化摘要命中同一任务。工具没有供应商或所有者参数。

## 状态与恢复

任务 queued → running → saving → completed/partial；失败、取消、交付失败和结果不确定分别保留。
每次调用前校验会话、工作区成员、模型启停与资源版本。参考图通过现有缓存和下载计量服务读取。
实际生成只提交一次；连接中断或无法确定上游结果时保留预留额度与请求标识，不自动重放。

已验证图片在交付前加密暂存在 PostgreSQL 任务记录（每张最多 20 MiB，最多 4 张），
交付资源成功的同一事务移除暂存正文。对象存储失败保留暂存，仅重试保存。
这会带来短期数据库容量开销；save_failed 任务需及时恢复，不能把此暂存当作另一份永久资源。
Worker 启动和可见任务状态查询可恢复 queued/saving；running 超时进入人工核对。
未确认的任务不能重新生成，管理员在核实上游后通过 tasks/{id}/resolve 结算确认张数并审计。

图片校验真实格式、字节与像素并移除元数据；结果地址仅接受固定公网 DNS 的 HTTPS 直连，
不跟随重定向。密钥、暂存正文、上游地址和提示词不进入公开任务响应或错误日志。
输出资源记录由任务关联，预览和下载通过原资源鉴权/流量接口。

## 计费

创建时冻结模型/连接版本、加密凭据、规格、每张积分及工作区倍率，预留请求张数的费用。
按通过格式验证的图片数一次结算；无效图片不收生成积分，少量成功释放差额。
资源交付失败不重复生成或扣费；用户取消后已生成图片仍保存并按实际数量结算。
生成费用与资源存储和下载分开，不改文字 Token 价格及历史账目，不增加工具费用。
成本参考单位为积分/张；上游 usage 和请求标识按实际保留，未配置成本参考即未知。
