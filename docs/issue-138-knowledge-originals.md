# #138 个人知识库原件切换与验收

知识库页面管理原件。云电脑在 `/home/user/knowledge` 读取本人原件，在 `/home/user/workspace` 读写个人资源。原件路径由库和文档 ID 决定。上传、替换和回收恢复通过知识库服务提交处理任务。知识库原件目录无需扫描或同步。

## 迁移演练和切换

1. 准备数据库和对象存储副本，记录源快照及对应的应用版本。在副本运行 `alembic upgrade head`。
2. 在 `backend` 下运行 `python -m app.migrate_knowledge_originals --report preflight.json`，检查所有条目。报告包括原路径、目标路径、摘要、当前原件数量、有效向量、每个账号的文档用量和引用状态计数。缺件、摘要不符、归属不明或无法确定当前原件的组必须先处理。只读预检不会改写副本。
3. 切换时先暂停新写入，等待上传和入库任务收尾，再停止 API、Worker 和清理任务。运行 `python -m app.migrate_knowledge_originals --execute --offline --report executed.json`。每组先复制并核验原件，再更新数据库。中断后可用新报告路径重跑。旧对象和切换前的数据库快照保留到验收完成。
4. 再跑只读预检，与切换前报告逐项对账。核对回收区、现有引用和知识库用量后恢复写入。若需回退，在暂停写入时使用切换前的数据库快照和旧对象，并核对切换后是否有需要另行保留的写入。

## 测试环境验收

- 网页上传本人两个库的有页码 PDF。启动一台云电脑，记录实例 ID、路径、页码和 SHA-256。尝试写入知识库路径应失败，普通资源路径应写入成功。
- 保持实例运行，从网页替换、删除及恢复原件。每次操作后重新打开文件，核对读到的字节和删除后的不可用状态。验证归属隔离和同名文件保留。
- 用已授权的测试模型核对问答和引用。相同摘要替换不增加处理任务，正文变化后旧内容退出检索，旧引用显示原文已变化。核对失败重试、重投及费用账单。

本地浏览器验收使用项目的上传测试 fixture。PostgreSQL 演练使用独立数据库和本地对象 fixture。云电脑供应商、实际对象存储及付费模型的联合验收需要测试环境授权。
