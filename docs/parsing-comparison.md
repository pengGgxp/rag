# MarkItDown 与按需 OCR 对比（Issue #59）

## 范围

按 2026-10-30 用户最新确认，本实验只比较文字提取与 OCR，不执行 Embedding、检索或模型问答。候选实现独立运行，不接入正式上传，不修改文档、索引、引用、用户账单或商业配置。真实文件和完整报告仅保存在未跟踪的 `output/`。

## 实现与复现

- 实验依赖单独锁定在 `backend/requirements-parsing-experiment.txt`，不加入正式运行依赖。
- Word 使用 MarkItDown 的 DOCX 转换器，保留标题、段落、表格与图片位置；相同图片在同文档内按 SHA-256 去重。图片封装为确定性 PDF，由现有 DocMind 识别。
- PDF 使用 MarkItDown 按页提取，再根据文字数量、异常字符、图片覆盖和文字层重叠判断是否调用整页 OCR。OCR 替换该页候选结果，不重复拼接。
- 3 份独立校准 PDF 固化 `calibration-v1`，12 份评分样本覆盖文字、表格、嵌套表格、图片、重复图片、扫描页、混合页、隐藏文字层与双栏。生成 PDF 表格是简单文字行，不能代表复杂单元格。
- 子进程禁止联网、设置文件/解压/图片尺寸和处理时间限制；主进程单独负责付费调用。SQLite 在提交前原子预留成本并保存任务 ID；已成功结果复用，不确定提交拒绝重发。
- 基线严格复用当前 Word 段落解析与 PDF DocMind 行为，不改正式实现。

在独立虚拟环境安装实验依赖后，从仓库根目录运行（PowerShell）：

```powershell
$env:PYTHONPATH = (Resolve-Path backend).Path
python -m experiments.benchmark --output output/parsing-comparison
```

首次命令只做本地转换，缺失 OCR 明确标记不完整。核实费率后，提供本地 JSON 费率文件并显式加 `--live-ocr --rates output/parsing-rates.json` 才能提交付费请求。真实副本可通过 `--additional-manifest` 加入，文件必须位于该实验 `samples/`，且校验 `source_sha256`；必须沿用原实验目录及成本检查点，不能重建目录绕过累计预算。

费率文件使用 `ocr.upper_yuan_per_page`、`source`、`verified_at`。本次于 2026-10-30 核实阿里云文档智能按量计费页面，采用最高解析档 ¥0.25/页作为保守上限，不依赖免费额度，也不将平台积分单价当作供应商人民币成本。

## 本次结果

15 份样本均完成两种方案解析：12 份固定生成文件、3 份现有 PDF 的只读副本（共 9 页）。真实副本已核对大小和 SHA-256，原业务数据未变。真实 Word、复杂合并表格及更多扫描件尚未充分覆盖。

| 检查项 | 当前方案 | 候选方案 |
| --- | ---: | ---: |
| 生成样本标注事实 | 18/24 | 24/24 |
| 真实 PDF 选定事实 | 6/6 | 6/6 |
| 生成 PDF 所需 OCR 页数 | 7 | 2 |
| 真实 PDF 所需 OCR 页数 | 9 | 1 |
| Word 图片所需 OCR 页数 | 0（未识别图片） | 2 |
| 总计 OCR 页数 | 16 | 5 |

这些数字是预先选定片段的检查，不是全文准确率。来源位置在事实自身的页或结构块范围内核对，不能借用同一切分块中的相邻来源。重复图片的多次出现保留，不能把正确的多次出现当成解析重复。

两方案共发起 14 个唯一 DocMind 任务、21 页，全部确认完成；按保守费率累计预留 ¥5.25，未超过 ¥20 上限，实际云账单尚未对账。没有执行 Embedding 或问答调用，没有扣用户积分。报告分别展示各方案页数、按上限计算的模拟费用、本次本地转换耗时和已记录的首次 OCR 等待时间；不将缓存复用速度当作首次处理耗时，OCR 等待也不冒充完整端到端耗时。

## 质量发现与采用建议

- **Word 表格及图片：建议作为优先正式接入方向。** 固定样本补出了当前方案遗漏的表格金额、嵌套内容和截图事实，重复图片只识别一次。纯文字 Word 不增加 OCR。尚需真实 Word 和复杂表格补测，不能据此宣称所有 Word 格式可靠。
- **简单文字 PDF：具备减少 OCR 的价值，尚不整体替换。** 固定样本保持已标注事实和页码；真实截图 PDF 仅识别含大图的一页，另页本地提取。小图漏识别、矢量内容、复杂阅读顺序仍有风险。
- **真实论文：保留现有方案。** 候选结果将英文标题和关键词排成伪表格，标题、作者粘连；虽然两个标注事实正确且省下 6 页 OCR，结构质量没有达到不退化门槛。不能只看字符数量或省钱下结论。
- **特殊文字层：需要修正。** 一份真实 PDF 的候选结果包含 44 个康熙部首字符，视觉近似常用汉字但字符不同；当前 OCR 结果使用常用汉字。现有异常字符阈值未拦住它。不能通过无差别 Unicode 归一化掩盖潜在数学符号变化。
- **扫描和混合 PDF：继续保留现有 OCR 能力。** 仅有局部文字不能证明整页可靠，当前候选整页 OCR 不拆散图表关系。不承诺所有复杂表格、双栏和隐藏文字层均已解决。

## 验证与后续边界

后端相关测试覆盖结构位置、图片去重、失败保留、混合 PDF 页码、预算并发、结果复用、不确定提交不重发及既有 DocMind/切分/预览回归。报告提供原文件入口、PDF 第一页预览、两方案原始提取文本、事实位置与 OCR 路径，按 1440px 和 390px 检查操作和截图。

本次不部署、不切换正式解析。不关闭 Issue #59：正式采用前仍需修正特殊文字层和论文结构问题，并补充真实 Word、复杂表格、全文文字准确率与更严格的顺序评测。下一步只围绕解析与 OCR 继续，不默认追加检索、Embedding 或问答实验。
