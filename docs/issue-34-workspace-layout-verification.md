# Issue #34 工作台布局验收

日期：2026-10-27。范围：工作台公共框架、标题、URL 导航、移动端抽屉和局部加载；不修改 API、数据、权限、计费或依赖。

## 实现边界

- `WorkspaceShell` 提供唯一公共侧栏和移动端抽屉，业务导航通过 `WorkspaceNavigation` 组合。
- `WorkspaceHeader` 统一标题、可选分区和操作区；`WorkspaceSkeleton` 提供局部加载骨架。
- 工作模式、知识库分区和会话以 Next 路由参数为准；设置拦截路由打开期间保留底层工作区参数。
- 用户选择使用 push，新会话获得 ID 和无效分区纠正使用 replace。轮询不会反向选择工作模式。
- 原会话切换或离开问答时停止生成；不新增后台生成或草稿持久化。
- 移动端文档行将操作放在下方，避免 44px 点击区域与文档状态重叠。

## 线上补充回归

首轮部署后，工作台主回归通过，真实登录会话的模式切换、刷新和设置关闭保留输入正常。但完整设置回归发现：直接加载设置页后切换分区，有时也命中拦截路由，使独立设置页和设置 slot 同时挂载。Issue 未因此关闭。

根布局增加最小的 `SettingsSlot`，根据默认路由分区决定是否显示设置 slot；默认分区本身是 settings 时，仅显示独立设置页。该判断不依赖 DOM、时序或业务模式，也不改变设置面板和 API。补充提交单独关联 #34，便于回滚；直接设置刷新后等待预取完成再切换的回归断言保留。
