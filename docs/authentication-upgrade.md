# 邮箱验证、微信登录与站点认证后台

## 目标和边界

实现 SMTP 验证邮件、邮箱验证码/密码登录、森遇微信登录及独立站点认证配置后台。
微信新身份完成邮箱验证后才创建账号、工作区和初始积分。旧账号需先登录、验证邮箱再绑定微信。
站点管理员与工作区角色独立，由服务器命令授权；本次不接短信，不部署邮件服务器。

## 验收和上线

覆盖验证码限流、过期、重放、并发消费，微信回调跨浏览器/会话校验、账号绑定冲突，站点配置越权和密钥脱敏。
执行后端测试、PostgreSQL 迁移验证、前端构建、Playwright 桌面和移动回归及 git diff --check。
新增认证策略默认关闭，既有会话保持有效。真实 SMTP 收信与真人微信扫码未通过前不得宣称完成端到端验收或开启强制验证。
部署备份数据库和镜像，仅更新 API/Web，保留数据服务和现有业务资料。

## 配置和恢复

站点凭据使用 SITE_CONFIG_ENCRYPTION_KEY 加密并存储于数据库。备份此密钥；数据库配置优先于旧 SMTP 环境变量。
首任站点管理员由 python -m app.manage site-admin grant --email 指定，不自动授予新注册者。
代码回滚不删除新增数据库字段/表。

## 实现说明

- 邮箱验证码与临时流程只存服务端，验证码用带服务端密钥的 HMAC 保存；浏览器只保存 HttpOnly 随机流程 Cookie。
- 已验证注册、微信绑定、工作区、初始积分与会话在同一事务中提交。PostgreSQL 行锁及身份唯一键处理并发。
- 森遇使用独立的自定义协议适配；授权码摘要单次消费，浏览器及绑定会话归属校验先于 code 交换。
- 旧 SMTP 环境变量只在数据库未保存 SMTP 配置时使用；独立加密密钥损坏时返回错误，不能静默切回旧配置。
- 新认证策略默认关闭，旧会话不批量撤销。首次邮箱验证无旧密码证明时清除旧密码并撤销旧会话。
- 为本任务新增的 AuthFrame 仅复用登录页静态品牌壳体；Authentication 负责邮箱/微信认证步骤，SiteAuthConsole 仅负责全站认证设置；沿用现有表单样式及 Radix Tabs，不新增依赖。
- 页面状态不持久化验证码和密码。认证步骤使用明确 URL，刷新从服务端恢复；邮件发送失败保留邮箱并允许重试。

## 运维与人工验收

使用 `scripts/deploy-authentication.sh` 保留数据库、自有配置密钥、旧源码及 API/Web 镜像；不会重建数据库、Redis 或存储容器。
`scripts/nginx-zhiku-auth.conf` 为现有试运行站点补充日志脱敏，回调授权码、状态路径和密码重置查询参数不得写入访问日志。

站点管理员首次使用顺序：配置邮箱 → 测试邮件并实际收信 → 验证本人邮箱 → 配置森遇应用 → 真人微信扫码确认动态回调路径保留 → 启用强制邮箱验证。
真实 SMTP 收信、微信首次/再次登录和绑定/解除绑定在获得业务凭据及真人扫码后继续验收；Issue #32 在此之前保持打开。

撤销站点管理员：`python -m app.manage site-admin revoke --email <邮箱>`。回滚使用 `rag-platform-api:before-auth-20261026` 与 `rag-platform-web:before-auth-20261026`，保留本次新增字段/表及加密密钥，不执行 Alembic downgrade。
