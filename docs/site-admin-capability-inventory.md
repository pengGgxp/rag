# 知库站点管理后台功能清单

- 状态：已确认，按 Issue #33 实现并验收
- 目的：明确站点运营后台的职责、已有能力与待补充能力
- 范围：站点级用户、工作区、全站审计和认证配置管理
- 实施跟踪：[Issue #33](https://github.com/pengGgxp/rag/issues/33)；下方能力盘点保留为实现前基线，实际验证记录见 `site-admin-acceptance.md`

## 1. 产品边界

知库需要区分三种工作空间，不能把站点运营能力塞入普通账号或工作区设置：

```text
用户工作台       /
个人与工作区设置 /settings/*
站点运营后台     /admin/*
```

- **用户工作台**服务于知识库、问答和 Agent 日常使用。
- **个人与工作区设置**服务于当前用户及其所在工作区。工作区成员、积分、计费规则和工作区审计仍由工作区权限管理。
- **站点运营后台**服务于整个平台的运维与用户支持，仅站点管理员可访问。它管理跨工作区的站点级对象，不继承或替代工作区角色。

所有站点后台 API 都必须在服务端校验 `is_site_admin`。前端隐藏入口只是导航体验，不构成权限控制。

## 3. 建议的后台导航

使用独立的站点后台布局和固定侧栏，页面之间通过路由切换，不使用嵌套全屏弹窗：

```text
站点管理
├── 概览
├── 用户
├── 工作区
├── 站点审计
└── 认证与登录
```

建议路径：

```text
/admin                  站点概览
/admin/users            用户列表
/admin/users/{userId}   用户详情
/admin/workspaces      工作区列表
/admin/workspaces/{id} 工作区详情
/admin/audit            站点审计
/admin/auth             认证配置（现有）
```

### 概览

- 展示站点级的基础运营数量，例如用户总数、近期注册数、工作区总数。
- 仅展示已存在且定义明确的数据，不展示虚构的健康灯、进度或“在线用户”。
- 概览不应成为带有大量图表的独立分析产品；需要处置的事项应可直接进入对应列表。

### 用户

- 按邮箱、姓名或用户 ID 搜索；支持分页和按注册时间、邮箱验证状态、账号状态筛选。
- 列表显示用户 ID、邮箱、姓名、邮箱验证状态、注册时间、所属工作区数量和账号状态。不得显示密码、验证码、OAuth token 或密钥。
- 用户详情展示账号基础资料、登录方式绑定状态、邮箱验证状态、创建时间、关联工作区及必要的积分账户概览。
- 提供受控的账号操作：停用/恢复账号、撤销会话、重新发送验证邮件（需有频控和审计）。只有明确产品需求和风险评估后，才开放邮箱修改、管理员角色变更等高风险操作。
- 站点管理员权限授予/撤销继续优先通过服务器命令管理；不在初版用户详情页提供容易误触的站点管理员开关。
- 不提供登录为该用户、读取用户密码、查看原始认证凭据等功能。
- 不直接物理删除用户。账号删除需要独立的数据保留、归属转移、账务及审计策略，未定义前不纳入后台操作。

### 工作区

- 跨站点查看工作区列表，按名称、创建时间、所有者/成员筛选。
- 工作区详情显示成员关系、创建时间、用户数、积分账户余额与累计使用等运营支持所需信息。
- 对话、文档和知识库内容默认不展示；支持排障必须另行定义授权、用途、记录和最小披露原则。
- 不把工作区管理员等同站点管理员，也不允许工作区管理员访问站点后台 API。

### 站点审计

- 统一查询站点后台的管理操作和安全相关认证事件，支持时间、操作者、动作、对象类型及结果筛选。
- 至少记录操作者、时间、动作、目标对象、结果和必要的变更摘要；高风险操作应记录变更前后允许公开的字段差异。
- 敏感值一律不写入审计：密码、AppKey、SMTP 密码、验证码、会话 Cookie、授权码、邮件正文和令牌。
- 审计记录应追加写入，不提供普通后台编辑或删除入口；保留期限和导出能力需明确策略。
- 区分站点审计、工作区审计和基础设施日志：容器/Nginx/API 运行日志属于运维观测系统，不应伪装成用户可读的业务审计。
- 当前 `site_auth_audit` 仅覆盖认证配置修改与测试邮件；落地统一站点审计前需确定是否扩展该表或建立新的站点审计模型，避免重复记账。

### 认证与登录

- 保留现有 `/admin/auth` 能力，纳入统一侧栏。
- 继续管理 SMTP、森遇微信配置和认证策略；写入操作展示明确成功/失败状态。
- 认证审计在统一站点审计中可查询，不再形成与全站审计割裂的管理入口。

## 4. 安全和权限约束

- 每个后台 API 在服务端重新读取用户站点管理员身份，不能只依赖登录时缓存的角色。
- 普通用户和工作区管理员访问站点 API 必须返回 403；列表、详情和聚合统计均需覆盖测试。
- 用户搜索和详情只返回运营支持必需字段；任何凭据、认证挑战、完整会话信息都不得出现在响应、日志或导出中。
- 停用、撤销会话、重发验证邮件和未来可能的账务修正均须记录操作者、目标、结果与理由，并具备防滥用频控。
- 站点后台不提供用户冒充登录。需要客服协助时使用可审计的只读信息与明确的用户授权流程。
- 涉及余额的人工调整不能直接改余额字段；如未来支持，必须通过积分账本的追加式交易、幂等键、理由和审计完成。
- 站点管理员授权仍由受控 CLI 完成，并对生产服务器操作留有变更记录。

## 6. 已确认的产品规则

按已批准开发计划执行：

1. 停用立即阻止新会话并撤销已有会话，恢复后可重新登录；不删除数据。
2. 站点管理员可重发验证邮件，按邮箱、IP、站点额度限制；同一用户至少间隔 60 秒，结果记审计。
3. 积分仅显示余额、累计入账、累计消耗，不展示逐笔账本或手工调账。
4. 配置只显示启用供应商数量和名称，不读取其密钥、接口地址或用户内容。
5. 站点审计包含管理和认证安全事件，保留 365 天，无后台编辑、删除或导出入口。
6. 物理删除、用户冒充及站点管理员角色开关均不在范围内；站点角色继续由 CLI 管理。
7. 防止误停管理员：先通过 CLI 撤销其站点角色，再执行停用；当前管理员不能停用自己。

本文的“当前已具备”和“需要补充”表格记录实现前状态，不单独作为验收结论。
