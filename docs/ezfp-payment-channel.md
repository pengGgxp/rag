# 易支付渠道接入

## 目标

在支付管理后台新增易支付（ezfp），保留现有支付 FM 渠道；管理员可分别配置渠道和官网链接，用户创建充值订单时可选择已启用渠道。

## 边界

- 首版只实现网页跳转充值，不实现退款、对账、JSAPI、小程序或代付。
- 易支付使用官方固定 HTTPS 下单地址、RSA-SHA256 签名和平台公钥验签；商户私钥与平台公钥加密存储，不回显。
- 订单绑定渠道及不可变配置版本；新配置只影响新订单，旧待支付订单仍按创建时的密钥验签。
- 两个渠道的充值档位各自维护，不变更积分价格、充值兑换关系及历史账单。
- 回调只在签名、商户号、订单号、订单金额和成功状态均匹配后入账；重复通知幂等。

## 验收

- 后台分别编辑并启停支付 FM、易支付，展示各自官网链接和回调地址。
- 用户可选择启用的渠道及其档位；API 不接受未启用渠道或其他渠道的报价。
- RSA 参数排序、签名、返回签名及回调签名符合官方文档；回调兼容额外签名字段。
- 配置轮换不影响旧订单；同渠道及跨渠道的回调不能互相入账。
- 覆盖错误签名、金额、商户号、状态、重复字段、超限响应和不安全支付 URL。
- 运行支付后端测试、PostgreSQL 迁移相关验证、前端构建和 `git diff --check`。

## 官方协议依据

- 接口说明：`https://www.ezfp.cn/doc/index.html`
- 签名规则：`https://www.ezfp.cn/doc/sign_note.html`
- 统一下单：`https://www.ezfp.cn/doc/pay_create.html`
- 支付结果通知：`https://www.ezfp.cn/doc/pay_notify.html`

验收时再以测试商户的真实端到端支付回调验证协议兼容性；开发测试不得发起真实扣款。
