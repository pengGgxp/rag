# 云电脑

## 接入约定

执行使用阿里 Agent Sandbox 极速版，锁定官方入门示例的 `e2b==2.31.0`。地域决定 `https://api.<region>.sandbox.aliyuncs.com` 与 `<region>.sandbox.aliyuncs.com`；不允许任意服务地址。参考：

- https://help.aliyun.com/zh/agent-sandbox/using-the-cloud-sandbox-via-the-sdk
- https://help.aliyun.com/zh/agent-sandbox/console-management-custom-templates

使用 `backend/cloud-computer.Dockerfile` 在阿里自定义模板流程构建模板。模板规格在供应商侧固定，后台规格字段为核对记录，不通过模型参数调整。构建后记录模板不可变 ID、实际 CPU/内存、地域和镜像摘要，再填写后台。Dockerfile 为待真实云构建验收的定义，不等于可用模板。

服务端持有 API Key，沿用 SITE_CONFIG_ENCRYPTION_KEY。后台读取不返回凭据；密钥留空保留、明确清除。不向沙箱注入业务凭据或长期存储密钥。OSS 挂载由供应商使用 RAM 角色签发限定挂载路径的临时身份，不把整个 Bucket 或其他工作区目录暴露给环境。

创建要求 secure、非公开访问、启用公网出站及网络拒绝列表。默认拒绝私网和元数据地址；云电脑不持有用户 Cookie 或平台业务凭据，接口仍须独立鉴权。管理员可按需补充拒绝地址，默认列表为空。迁移 0057 移除旧配置中自动加入的两个业务域名，保留其他管理员规则，不改历史会话快照；已有实例需结束后重建才能应用新策略。真实验收需实测 DNS 重绑定、IPv6、内网及元数据；未通过不能宣称隔离验收完成。

## 生命周期和资源

模型可按任务显式创建多台云电脑，并通过稳定的 `computer_id` 查询、复用或结束实例。实例归属当前用户和工作区，同一工作区可跨对话复用；创建来源对话只用于记录，不决定后续执行路由。平台不设活动实例数量上限。默认闲置 600 秒，最长 3600 秒。命令执行中不算空闲，供应商硬期限始终生效。

模型使用 `create_cloud_computer`、`list_cloud_computers`、`get_cloud_computer` 和 `end_cloud_computer` 管理实例。`run_command`、文件操作、`read_image` 和预览操作都必须携带目标 `computer_id`；缺少或不可用时返回明确状态，不自动创建或切换实例。创建独立完成供应商实例创建和初始化。工作目录 `/home/user/workspace` 直接挂载工作区资源目录；Skill 上传后作为普通文件保留在 `skills/<导入目录>/`，通过 `list_files`、`read_file` 发现和读取，再按实际路径执行，依赖位于 `/tmp/zhiku-cloud-computer/deps`。资源文件不再准备输入、保留历史版本或复制归档；依赖和缓存目录不在资源列表展示。文件工具及命令直接使用当前文件，不计应用层模型读取流量。

支持图片输入的模型可直接调用 `read_image` 查看云电脑文件系统中的图片，无需用户配置读取范围。模型可按任务组合命令、文件读写和图片读取工具；需要远程图片时可自行在云电脑中获取并处理后读取，不规定固定工具顺序。图片路径遵循云电脑执行身份及文件系统权限；图片工具不增加专属路径、文件名或符号链接限制。云电脑命令结果只保留安全元数据，不保存图片正文或 Base64。图片按实际内容校验 PNG、JPEG 或静态 WebP、完整性、10 MiB 字节上限及 4000 万像素限制。已有运行环境直接复用；无环境时按需启动，用户停止请求时终止等待。

新建云电脑启用公网出站，供命令工具按需获取公开资源；现有私网和特殊地址拒绝规则及管理员拒绝项保留，不增加公网目标白名单。此设置影响云电脑中的所有命令，不仅是图片获取。公网入站仍要求令牌鉴权。该网络设置应用于新建环境，已有活跃环境不会因此自动变更。

API 将命令持久化后投递现有 Celery Worker；Agent 等待结果，页面独立查询。多条命令可在同一实例并行运行，各自取消和记录回执。API 每 15 秒扫描并独立维护活跃环境，慢实例不会阻塞其他实例。创建或已提交命令结果未知不重放；创建按持久化调用身份查找原实例，结束意图在远端状态确认前保留。供应商硬期限限制 API/Worker 同时离线产生的损失。

### OSS 资源挂载

主存储为 OSS 时，在后台填写可由 `fc.aliyuncs.com` 扮演的 `oss_role_arn`。同一工作区所有环境使用固定前缀 `workspaces/{workspace_id}/resource-directory/`，挂载到 `/home/user/workspace`。通过动态挂载 metadata 指定 Bucket、Endpoint、前缀和角色；创建时只将当前 Bucket 对应的 `{bucket}.oss-{region}.aliyuncs.com` 加入沙箱出站允许规则，私网与元数据地址拒绝规则仍生效。挂载访问继续受供应商角色和挂载路径限制。

上传、图片生成和文件写入直接使用该目录；云电脑启动不创建会话副本。同工作区不同会话及不同云电脑可见同一份当前文件，按共享文件语义处理并发写入。模型自行组织目录和文件名；显式覆盖按普通文件操作处理。补丁保留现有冲突检查，但不对任意 Shell 同路径竞争写入作全局仲裁承诺。索引登记通过工作区锁串行。一次性迁移预检缺失、路径冲突及内容摘要，事务提交当前索引；原对象仅作为离线发布回滚备份，不作为可访问历史版本。

命令结束和销毁不扫描、不归档、不复制正文。资源列表根据对象元数据发现新建、修改及删除；下载前 HEAD 校验当前文件。聊天引用读取当前文件，删除后显示不可用；删除后同名重建生成新资源身份，不恢复已经失效的旧聊天引用。销毁环境不清空共享目录，不重放命令。

云电脑文件操作不扣应用层内部下载额度；云电脑存续费、资源存储和用户实际预览/下载分别计量。图片发送给外部模型时仍需读取图片，不等同于云电脑操作。供应商 OSS 请求/流量成本与用户下载账目分离，不宣称云侧零成本。

共享目录允许直接写入，应用不能在任意 shell 文件写入前原子拦截容量。上传与新命令准入检查容量，列表和计量按 OSS 元数据更新；不宣称有文件系统硬配额。发布记录见 `docs/tasks/shared-resource-directory.md`。

角色权限示例与阿里官方说明见任务记录，必须同时具有 Bucket 列举及目标前缀对象读写权限。角色权限是上限，供应商进一步限定单次挂载路径。真实跨前缀越权攻击、IPv6 和 DNS 重绑定尚未完成专项验收，不能将普通隔离测试称为完整安全审计。

结束、空闲和余额不足时停止命令，再销毁并查询确认。文件已经位于挂载目录，不做结束同步。平台回收延误不转嫁用户。服务重启后运行维护核对。

## 计费

计费主体沿用现有工作区积分账户，记录操作用户。经用户授权，初始配置默认每分钟 1 积分，管理员可调整，默认不启用。按存续秒数累计，包含命令间等待；累计总额统一保留四位小数，周期入账仅记累计差额。首次预留一个闲置窗口，每分钟结算并补足预留；不足时结束，不允许透支其他任务的预留。

预留及释放复用原账本，不计入最终消费；费用类别为 `cloud_computer`。每个环境冻结售价和配置版本，后台调价不改变活跃环境。模型 Token、资源存储及下载费用继续独立核算。云侧实际成本需账单核对，不能用用户积分流水冒充云账单。

### 结束原因与预留不足（Issue #114）

结算返回 `CONTINUE`、`INSUFFICIENT_BALANCE`、`RESERVATION_EXPIRED` 或 `STOPPED`，
不能将所有停止计费结果解释成余额不足。仅实际可用余额不足以预留完整闲置窗口时，
记录 `insufficient_balance`。例如单价 2 积分/分钟、闲置窗口 600 秒时，
每次续期仍需预留 20 积分；余额为正也可能无法满足完整预留。

后台核对延迟使累计费用超过已结算与当前预留总额时，沿用既有费用上限，
停止计费并结束环境，记录 `reservation_expired`，不追收超过预留覆盖范围的费用、
不自动续期或重启。此类情况不以账户余额推断原因，也不向用户报积分不足。

`cloud_computer_sessions.stop_reason` 是可空的原因码，通过条件更新保留首次确认原因，
与运行状态和内部诊断 `error` 分离。原因还包括 `user_requested`、`idle_timeout`、
`max_lifetime`、`access_revoked`、`execution_interrupted`、`provider_ended` 和 `startup_failed`。
后续清理或重复结束不覆盖已记录原因；历史记录不从旧错误文字反推原因。

销毁未确认时仍为 `stopping`；只有确认销毁或实例不存在才记录终态和最终结算。
状态摘要由 `status` 决定，已结束始终显示“云电脑已结束”，内部错误不覆盖摘要。
迁移 `0073_cloud_stop_reason` 仅增加可空字段，不回填历史原因、不修改余额或账单。
迁移回滚策略为 `automatic-app-rollback`：旧应用可容忍新增可空列，
应用回退无需数据库降级；旧字段和计费契约保持不变。

## API

- `GET/PUT /site/admin/cloud-computer`：版本化设置，管理员权限。
- `POST /site/admin/cloud-computer/check`：只验证列表连接，不创建实例、不验证模板。
- `GET /cloud-computer/catalog`：可用性、单价、闲置和最长时间。
- `GET /cloud-computers`、`GET /cloud-computers/{computer_id}`：按工作区列出或查询实例及费用。
- `POST /cloud-computers/{computer_id}/end`：请求结束指定实例。
- `GET /cloud-computers/{computer_id}/commands`：查询该实例命令回执，不返回云凭据或模型输入。
- `POST /cloud-computer/commands/{id}/cancel`：停止对应命令。

所有用户接口重新验证登录、用户和工作区归属；写操作要求编辑权限并沿用全局 CSRF/来源校验。

上述环境状态响应及预览附带的 `computer` 统一增加：

- `stop_reason`：可空原因码；未知时为 `null`。
- `stop_reason_text`：按当前状态生成的用户文案，与 `summary` 分开展示。
- `renewal_required_credits`：仅 `insufficient_balance` 返回本实例冻结配置计算的续期预留积分字符串，其余为 `null`。

聊天控制栏按实例呈现状态、费用和独立结束操作；模型负责选择目标，界面查看状态不会改变执行路由。结束中不显示最终消费；费用详情仅在真实预留不足时展示续期门槛。

## 对话中的状态与费用（Issue #107）

成果区提供就绪预览、查看文件及原有计量下载。输入框上方保留实际环境状态、
费用详情和结束入口，不再重复显示滚动积分或单价。费用详情按需展示服务端累计值、
启动时冻结的单价、已运行秒数及两种截止时间；仍保留最多四位小数。

`cloud-computer-state.ts` / `cloud-computer-context.tsx` 提供按登录用户和工作区隔离的
内存状态源。页面前台每五秒核对，恢复可见时立即核对；不在本地推算费用。
退出、撤权和作用域切换清除数据并拒绝旧请求回写。结束中/已结束优先于迟到的轮询、
授权和心跳响应；新环境使用独立环境 ID。

结束操作提交后保留“正在结束”，直到现有接口确认 terminal，才展示最终费用。
查询失败保留最后已知结果并提供刷新，操作响应丢失不会冒充结算成功。
停止当前命令不停止独立预览；关闭预览不调用结束接口，恢复原有闲置规则。
Issue #107 的界面改造没有数据库或 API 变更，也没有调整计费、权限、预留、回收和文件持久化规则。
后续结束原因字段与迁移见上文 Issue #114。

## 上线与验收

新增迁移 `0056_cloud_computer`，不改历史账单。先完成模拟和 PostgreSQL 测试，再确认真实云预算、模板、网络策略、销毁及云侧用量。真实模型调用不在当前授权范围内。

上线前备份数据库、配置及镜像；确认旧 Docker 执行没有运行任务。管理员在供应商控制台先创建模板并将模板 ID 填入站点后台；平台不构建或自动创建供应商模板。迁移后协调更新 API/Worker/Web，配置真实连接、模板和经确认的售价并完成实际启用验证，再停止旧执行服务。没有真实凭据、模板或售价时不得宣布上线完成，也不自动退回 Docker。
