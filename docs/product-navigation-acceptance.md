# 产品导航调整

对应 Issue #12。目标是采用成熟 RAG 产品的工作流和信息层级，
把资料维护、知识使用和工程诊断分开，而非只替换配色或文案。

## 参照与映射

主要参照 RAGFlow，文档维护参照 Dify。参考材料为公开官方文档与操作截图，
不声称已登录这些产品完成全流程试用，也不声称像素级复制某个版本。

- RAGFlow 知识库概览：https://ragflow.io/docs/dataset_overview
- RAGFlow 知识库列表：https://ragflow.io/docs/dataset_list_and_creation
- Dify 文档维护：https://docs.dify.ai/en/cloud/use-dify/knowledge/manage-knowledge/maintain-knowledge-documents
- Dify 检索测试：https://docs.dify.ai/en/use-dify/knowledge/test-retrieval

| 官方产品组织方式 | 本项目对应实现 |
| --- | --- |
| 知识库列表进入具体知识库 | 首页为可搜索的知识库卡片目录，点击进入文档列表 |
| 知识库内部区分文件维护、检索测试、配置 | 库内侧栏为“文档 / 检索测试 / 配置” |
| 聊天独立于知识库维护 | 产品导航单独提供“知识问答”，管理页可前往当前库问答 |
| 文档表格以文件和处理状态为中心 | 保留搜索、上传、状态、时间、大小、预览、删除与恢复，移除统计大块及索引遥测 |
| 模型和检索参数归入配置 | 配置页只读展示真实信息；服务级模型标注为“当前服务配置”，不伪装成库级可编辑项 |
| 来源核对是回答主流程 | 回答保留正文、引用和原文预览；检索记录进入折叠的“回答详情” |
| 调试信息按需查看 | 检索测试中的排名指标默认折叠；服务配置状态仅放“系统诊断”窗口 |

## 范围与边界

不改变后端 API、数据库、检索策略、证据阈值、删除语义或认证边界。
不添加假账户、假权限、假模型选择器、虚构统计或尚未实现的工作流菜单。
Docker 是部署方式，不再作为产品身份；正常页面不展示 LOCAL、Docker 状态、
向量维数或模型状态条。用户上传的正文、知识库名称和描述不做字符串清洗。

保留真实上传、原文、回收站、问答、引用、检索测试和 Trace 检查。
切换知识库继续取消旧回答请求、清空旧问答与预览，并隔离过期文档响应；
离开检索测试会取消其未完成请求。

## 验证

验收要求：生产构建、后端回归、桌面及移动端截图、
新建与上传、文件搜索、删除恢复、真实云端问答、引用及 Trace 查看、
检索测试及取消、库切换时过期响应隔离、失败状态、无横向溢出。
