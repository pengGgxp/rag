# 图片与文件问答

Issue #56。目标是让用户在现有问答输入区直接提供图片、文件，再通过同一条问答与 Agent 链路分析。
不改变模型价格、工作区倍率、默认选择或 Issue #36 结算开关，不将附件自动变为知识库文档。

## 能力与边界

- 支持图片输入的模型可自主调用 `read_image` 按需查看云电脑文件或公开图片 URL；
  用户无需预先配置读取范围。该能力只读，不会写入、删除或执行图片内容中的指令。
- 本地图片沿用当前会话云电脑；未启动时按现有会话环境流程启动，并按云电脑存续时间计费。
  远程图片在服务端读取，不启动云电脑，也不新增图片读取费或用户可见配置。
- 模型新增显式 `supports_images`，现有模型默认关闭，管理员按已核实的真实能力配置。
  模型列表安全返回该字段，配置与已有模型版本一起保存。
- 图片支持 PNG、JPEG、静态 WebP，单张 10MiB、最多 4000 万像素；
  文件支持 PDF、TXT、Markdown、CSV、DOCX、XLSX，单份 20MiB。
  每次最多 6 份、总计 40MiB；文档最多 10 万字符，PDF 最多 200 页。
- 文档通过本地解析获得文字，不调用付费 OCR、不产生 Embedding 或知识库索引。
  扫描 PDF 无文字时提示改传页面图片或加入知识库，不假装已读取其中的图表、扫描内容。
- 上传只产生私有草稿，24 小时过期；发送事务将附件绑定到一条用户消息。
  同一附件不能绑定多个请求，失败回答使用原消息附件重试。
- 原始文件保存 COS 私有 `_chat/` 对象；响应只有名称、类型、大小和 ID。
  预览、下载、发送均校验账号、工作区和会话权限，删除会话后立即不可访问，
  由现有维护任务清理对象、过期及放弃的草稿；未登记孤立对象延迟清理。

## 接口与调用

- `POST /chat/attachments`：单份 multipart 上传并验证，返回安全元数据。
- `GET /chat/attachments/{id}/content`：认证读取；图片预览、文件下载；禁止缓存。
- `DELETE /chat/attachments/{id}`：移除未发送附件，已发送附件随会话保留。
- 发送请求新增 `attachment_ids`；问题和附件至少有一项，重试不能混入新附件。
  当前图片或尚未压缩的图片历史遇到不支持图片的模型，在预授权前拒绝。
- Chat Completions 使用 `text` / `image_url`，Responses 使用 `input_text` / `input_image`。
  Anthropic、Gemini 使用各自原生图片内容；服务端校验原始文件摘要后转为本次模型请求的内嵌图片；
  不向模型或浏览器暴露私有对象键。
- 各轮历史、工具调用和重试保持附件；上下文估算使用图片尺寸，不计量 Base64 字符数。
  压缩时图片仍作为图片输入，不把内部描述符序列化成提示词。原始附件不删除。
- `read_image` 的本地路径绝对路径原样校验，相对路径以 `/home/user/workspace` 为基准；
  拒绝路径穿越、反斜杠、控制字符、符号链接、非普通文件、敏感目录及密钥类文件。
  远程地址仅接受公开 HTTP(S) 标准端口，每一跳重新校验 DNS、协议和端口，最多跟随 3 次跳转。
  图片依据实际内容识别为 PNG、JPEG 或静态 WebP，沿用单张 10MiB、4000 万像素限制并校验完整性。
- `read_image` 按模型需要读取图片，需要再次查看同一路径或 URL 时由模型重新调用。
  图片字节不进入工具事件、公开响应、日志、云电脑命令结果或续传记录。
  工具活动只显示“查看图片”、文件名及完成或失败摘要，不展示沙箱绝对路径、URL 查询参数或预览。
- 附件是用户提供的不可信资料，不能覆盖系统规则，不为其制造知识库 chunk 引用。
  现有计费继续来自模型实际 usage；没有单独的附件、图片上传或解析次数费。

## 前端责任

`ChatAttachments` 只负责草稿上传、私有预览、移除和安全下载，复用现有 Tooltip/Dialog；
知识库上传弹窗不能承担对话附件的消息归属和生成禁用状态，因此不复用它的业务状态。
不新增依赖、浏览器存储或第二套弹窗。关闭页面不保存未发送文件，历史消息保留已发送文件。
