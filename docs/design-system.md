# 知库设计系统规范

- 状态：已确认，作为前端开发约束
- 适用范围：知库 Web 前端、知识库工作台、知识问答、Agent 状态、账号与计费界面
- 关联 Issue：[Issue #10](https://github.com/pengGgxp/rag/issues/10)、[Issue #19](https://github.com/pengGgxp/rag/issues/19)
- 最后更新：2026-10-29

## 1. 产品气质

### 对话思考与管理员验证（Issue #49）

- 思考是对话中的逐轮内容，不是全局消息标题；沿用活动轨迹的轻量展开入口、
  中性文字、细分隔线和 Agent 状态色，不新增嵌套卡片或常驻模型徽章。
- 只在收到真实思考片段后显示“正在思考”；默认生成时展开、结束时收起，
  用户手动选择优先。手机入口至少 44px，尊重 reduced motion，不强抢滚动位置。
- 参数、版本、逐轮推理用量和验证诊断只属于站点后台，不进入普通对话或“回答详情”。
  “回答详情”只保留与答案追溯有关的模型、思考模式和资料来源，不展示“已收到思考内容”
  或 Token 等内部执行统计，也不以另一段诊断状态文字替代。
- 参数验证复用模型表单、未保存提示和内联费用确认；预览与真实付费测试明确区分，
  不将“接口返回成功”包装成“思考效果已验证”。
- 新增 `ConversationThinking` 负责单轮展开和权限读取，复用活动入口样式；
  不承担模型配置或结算。`ThinkingDiagnostics` 负责现有模型表单内的预览与测试，
  不建立新的菜单、窗口或导航体系。

知库是一个长期使用的知识工作空间，不是营销落地页，也不是后端调试面板。
界面应同时具备两种气质：

1. **Calm Knowledge Workspace**：文档、知识库和配置界面稳定、清晰、耐用。
2. **Developer Intelligence**：检索详情和 Agent 工具调用保留技术产品的密度与可观察性；系统级诊断不作为普通用户导航入口。

表达型动效只用于 Agent 的关键状态和重要反馈，不让整个工作台变成动画展示页。

### 1.1 设计原则

- **先表达状态，再表达装饰**：用户始终能知道正在发生什么、是否完成、下一步能做什么。
- **信息密度服务于工作**：优先支持扫描、比较、定位和恢复操作。
- **复杂信息按需展开**：默认展示结论，引用、Trace、工具调用和诊断信息逐层展开。
- **真实状态优先**：不制造虚假的进度、在线状态、模型状态或处理结果。
- **可恢复**：错误保留用户输入，危险操作明确，删除优先采用可恢复的回收站语义。
- **视觉统一但不单调**：中性表面承载内容，Cobalt 建立产品识别，Indigo 表达 Agent，Cyan 表达引用与检索，语义色只承担语义。

## 2. 技术基线

以下库是项目的唯一默认入口，不为相同职责引入第二套方案：

| 能力 | 规范入口 | 约束 |
| --- | --- | --- |
| 无障碍交互基元 | Radix Primitives | Dialog、Tabs、Tooltip、Popover、Menu 等优先复用 |
| 可控组件源码 | shadcn/ui 风格组件 | 组件源码放在项目内，允许按产品需要修改 |
| 动画 | `motion/react` | 统一由 Motion 实现组件和状态动效 |
| 图标 | Lucide | 不混用其他图标库，不手写重复图标 |
| 跨页面 UI 状态 | Zustand | 仅管理真正跨视图的 UI 状态 |
| 可调面板 | `react-resizable-panels` | 只有出现真实可调面板需求时才引入 |
| 拖拽 | `dnd-kit` | 只有出现真实拖拽工作流时才引入 |
| 浏览器验收 | Playwright CLI | 桌面、移动、键盘和关键业务流必须可复验 |

### 2.1 依赖规则

- 一个职责只保留一个默认依赖。
- 不为了一个小交互引入完整组件库。
- 不复制组件库的内部实现到业务组件中。
- 业务组件可以组合基础组件，但不得绕过 Radix 的焦点、键盘和关闭行为。
- 新增依赖前说明它解决的真实问题、替代方案和移除成本。

### 2.2 组件复用与扩展规范

- 创建组件前，必须先检索 `frontend/components/ui` 和现有业务组件，确认没有可直接复用的入口。
- 同一职责只能有一个默认组件入口；现有组件能通过 props、variant 或组合满足需求时，必须扩展现有组件，禁止复制近似实现。
- 基础交互组件放在 `frontend/components/ui`，功能组件放在对应业务目录；页面不得直接复制另一页面的完整实现。
- 不创建带大量模式参数的“万能组件”；只复用稳定的交互基元，保持页面和业务模块的边界清晰。
- 新组件必须在提交说明中记录：现有组件为何不能满足、新组件职责边界、可复用的 props 或状态，以及无障碍、动效和测试方式。
- 颜色、间距、圆角和动效优先复用设计 Token，不在新组件中散落临时值。
- 新增依赖前必须说明真实需求、现有方案为何不足以及未来移除成本。
- 提交前检查是否产生重复按钮、弹窗、侧栏、加载状态或导航实现。

## 3. 视觉 Token

所有颜色、间距、圆角、阴影和动效参数都应先定义为语义 Token，再在组件中使用。
禁止在业务 JSX 中散落不可解释的颜色值和时长值。

### 3.1 颜色层级

推荐建立以下语义层：

```css
--background
--surface
--surface-raised
--surface-muted
--text-primary
--text-secondary
--text-tertiary
--border-subtle
--border-default
--brand
--brand-foreground
--interactive
--interactive-hover
--focus-ring
--success
--warning
--danger
--info
```

颜色使用规则：

- 页面背景和工作区表面以中性灰白为主。
- **Cobalt** 是产品主色，用于主按钮、当前导航、选中状态和主要交互。
- **Indigo** 只用于 Agent、模型执行和表达型 AI 状态，不作为全局背景。
- **Cyan** 用于引用、检索、来源链接和知识定位。
- **Emerald/绿色** 只表示成功、已完成和健康状态，不再承担品牌色。
- 红色表示危险或失败，Amber 表示等待或警告，不能作为普通装饰。
- 文本和边框必须满足可读性对比度。
- 暗色模式如果实现，必须复用同一套语义 Token，不单独写一套业务颜色。

### 3.1.1 已确认主题

```css
/* 产品主色：Cobalt */
--brand: #2563eb;
--brand-hover: #1d4ed8;
--brand-soft: #eff6ff;

/* Agent 表达：Indigo */
--agent: #4f46e5;
--agent-soft: #eef2ff;

/* 引用与检索：Cyan */
--reference: #0891b2;
--reference-soft: #ecfeff;

/* 中性工作台 */
--background: #f8fafc;
--surface: #ffffff;
--surface-muted: #f1f5f9;
--text-primary: #172033;
--text-secondary: #64748b;
--border-default: #e2e8f0;
--focus-ring: #2563eb;

/* 仅用于真实语义 */
--success: #16a34a;
--warning: #d97706;
--danger: #dc2626;
```

主题组合规则：

- 页面大面积使用 `background`、`surface` 和 `surface-muted`，不铺品牌色。
- 同一视图只允许一个主操作色；Agent 状态和引用可以使用各自的辅助色。
- 不使用蓝紫渐变、整页紫色背景或大面积高饱和色块。
- 状态颜色必须同时有文字、图标或结构表达，不能只靠颜色区分。

### 3.2 排版

- 中文优先使用系统无衬线字体，保留 `Microsoft YaHei` 等中文回退。
- 页面标题只在真正的页面入口使用大字号。
- 工作台、表格、侧栏和弹窗使用紧凑标题，不使用营销式超大标题。
- 正文行高优先保证阅读，表格和元数据可以更紧凑。
- `letter-spacing` 默认保持为 `0`，不使用负字距挤压中文。
- 数字、时间、积分和模型参数使用等宽数字或稳定的数字对齐方式。

### 3.3 几何与表面

- 默认圆角为 6px 或 8px；仅在现有组件行为确有需要时使用更大圆角。
- 页面分区使用整宽布局或约束容器，不把每个区域都包成卡片。
- 不允许卡片套卡片。
- 卡片只用于重复条目、弹窗和确实需要边界的工具。
- 阴影应表达层级，不用于制造装饰性浮层。
- 不使用渐变球、光晕块、玻璃拟态噪声作为常规背景。

## 4. 页面与信息架构

### 4.1 工作台

- 左侧导航负责知识库、问答和扩展入口。
- 主区域负责当前任务，不同时展示互相竞争的多个主入口。
- 面包屑只表达当前层级，不重复完整导航。
- 页面标题下方优先放当前状态、范围和关键操作。
- 主要操作使用一个明确的主按钮，其余操作降级为次按钮或图标按钮。

### 4.2 知识库与文档

工作台布局统一约定（Issue #34）：

- 知识库、知识问答、Agent 扩展共用 `WorkspaceShell`、`WorkspaceSidebar` 和 `WorkspaceHeader`；业务模块通过 `WorkspaceNavigation` 将局部导航放进公共侧栏，业务状态仍由所属模块管理。
- 桌面侧栏 232px，701–1100px 为 218px；700px 以下使用 260px 的 Radix Dialog 抽屉，复用现有 Dialog 的焦点约束、Escape 和关闭后焦点恢复。
- 公共标题栏桌面 60px、移动端 56px；标题 18px/600，左右间距桌面 32px、移动端 16px。对应 CSS Token 为 `--workspace-sidebar-width`、`--workspace-drawer-width`、`--workspace-header-height`、`--workspace-title-size`、`--workspace-content-padding`。
- 每页只有一个公共 h1：知识库列表为“知识库”，内部为当前库名称及分区；问答为会话标题或“新对话”；扩展为“Agent 扩展”。不在内容区重复标题。
- 操作区靠右固定，长标题省略并提供可聚焦 Tooltip；局部状态、搜索、页签和编辑器留在内容区。手机图标操作至少 44px 点击区域。
- 业务内容局部滚动、加载及重试，公共侧栏与标题不随请求隐藏。聊天输入框固定在聊天区域底部，消息列表独立滚动。
- 设置浮层及站点后台保留原布局，不新增依赖。新增 Header 是现有三套标题的唯一入口；导航插槽只负责 DOM 放置，不负责加载数据或管理业务状态。

- 知识库列表优先支持搜索、选择和进入。
- 文档列表以文件名、处理状态、版本和更新时间为核心。
- 处理中、失败、已删除和已归档必须有清晰且可读的状态。
- 原文预览、引用详情和版本信息按需展开。
- 删除、归档和恢复必须给出明确反馈，不使用静默状态变化。
- 上传复用工作台唯一的 Radix Dialog；跨页面任务由 `DocumentUploadProvider` 持续管理，侧栏底部提供紧凑任务入口。每个文件独立显示真实字节进度与暂停、继续、重试、取消，不因关闭窗口或切换知识库而中断；切换工作区暂停传输且隐藏其他工作区任务。
- “传输完成 / 正在校验 / 文档处理中 / 可检索”分别表达，只有真实索引完成才显示可检索。刷新后的续传使用重选原文件入口，不保存文件内容或签名链接；分片不符时明确拒绝拼接。
- 上传窗口使用中性表面、Cobalt 进度和既有 Token，不沿用独有的绿色装饰。标题及关闭入口在长任务列表滚动时保持可见，手机操作至少 44px。
- 文件存储属于站点后台配置，沿用模型详情表单分区、未保存提示和版本冲突交互；凭据留空保留、明确清除，不回显密钥。连接测试成功不等于已完成原文件迁移或浏览器跨域验证。
- 存储配置页面只展示配置表单和必要的操作反馈，不常驻迁移阶段、配置版本、上传容量或测试步骤说明。一次性文件搬运属于部署操作，不进入日常管理界面；连接测试仅反馈连接结果，不暗示存储已启用。

### 4.3 问答与 Agent

- 回答正文是主内容，引用、回答详情和 Trace 是可展开的辅助层。
- 行内来源复用数字引用按钮和现有来源详情，兼容 `[实际chunk_id]` 与
  `[chunk_id: 实际chunk_id]`。只转换当前回答已授权来源内的 ID，重复来源编号一致；
  不改写代码块、行内代码或已有链接，不给未知 ID 制造可点击来源。
- Agent 的思考、检索、工具调用和完成状态要能被用户理解，但不展示无意义的内部日志。
- 工具调用展示“正在做什么”和“结果是什么”，参数和原始响应按需查看。
- 没有证据时显示明确拒答，不用动画掩盖缺少证据。
- Agent 失败时保留已生成内容和可恢复操作。
- 模型选择只有一个入口：知识问答输入工具栏，Agent 复用同一发送链路。所有工作区成员均可为本次请求选择可用模型；生成期间禁用切换。
- 思考设置紧邻模型选择器，使用轻量内联文字与 Lucide 图标入口，显示模型实际支持的等级、开关或预算，不使用跨模型通用强度滑块。未配置/不支持隐藏，固定思考只读，生成期间禁用。切换模型恢复其默认值，不持久化到会话或浏览器。
- 模型设置内的思考表单沿用同一分区、表单网格、保存和未保存确认；等级用复选框选择真实支持集合，预算用带名称的数值预设，不新增弹窗或任意 JSON 编辑器。请求思考设置收进回答详情，协议续传不展示；真实可展示思考按逐轮规则呈现。
- 思考表单必须使用实际定义的 `--ink`、`--muted`、`--line` 和 `--form-*` Token；复选框沿用启用模型的 16px/Cobalt 样式。等级行共享表头、对齐参数与显示名称，不在每个桌面行重复标签；工具兼容、仅流式等低频选项收进可键盘展开的高级设置。预算复用 `policy-input` 单位后缀。
- 问答的模型与思考选择器默认无独立表单边框，继承字体，以悬停表面、展开状态和焦点环表达交互。收起时仅显示模型名称与思考选项；展开后的锚定列表分层显示模型标识、选项实际值、当前勾选及不可用原因。模型超过五项时提供搜索，空搜索结果明确反馈。手机同一行排列，名称省略、详情在展开后完整可读，入口和发送按钮至少 44px。
- 选择仅保留在当前页面的 React 状态，连续发送、新建或切换会话沿用当前选择；刷新、重新进入页面或切换工作区恢复站点默认模型，不写入会话或浏览器持久化。
- 模型列表只显示名称、模型名及安全的不可用原因；不虚构速度、智能评分或价格标签。`RequestModelPicker` 只负责组合现有 Dialog/Tooltip 与列表，不加载数据或映射上游参数。现有 Dialog 的 anchor 模式负责无额外遮罩的定位、Escape、外部点击和焦点返回，使用 `--selection-shadow`、`--selection-radius`；不新增第二个弹窗依赖。支持方向键、Home/End，搜索按向下键进入选项。加载、空列表、失败及重试在输入区局部呈现，失败保留问题。实际模型快照只在回答详情显示，不常驻每条消息下方。
- 对话执行反馈逐次插入正文流中，使用“正文 → 本次工具活动 → 后续正文”的有序展示块；每次调用都有独立且持久的活动行，不集中放在消息顶部，不合并隐藏后续调用。等待、执行、成功、失败、取消同时有图标与文字；只有真正开始执行才显示进行中。完成后在原位置折叠为自然语言摘要，主动展开的活动保持展开。`ConversationActivity` 只处理安全摘要的呈现与展开状态，不执行工具或解析原始参数。
- 上下文入口紧邻输入工具栏，复用 Dialog anchor 展示估算输入、输出预留、安全余量及整理操作。未配置容量不显示百分比；手动整理使用内联计费确认，不再嵌套 Dialog。`ConversationContextControl` 不自行请求模型或计算费用。视觉样稿仅开发环境可见，未经视觉确认不接正式功能、不部署样稿数据。
- 上下文状态须区分未选模型、加载、读取失败与实际容量缺失；只有成功读取配置后确认缺失才提示管理员配置。新对话使用模型列表中的安全容量信息显示就绪状态，尚无实际输入估算时不显示零用量或百分比；切换模型或会话取消旧请求，失败提供对应数据源的局部重试。

### 4.4 账号与工作区

- 设置复用 Radix Dialog，桌面为居中窗口：最大宽度 1120px、视口两侧至少 24px、高度 `min(760px, 88dvh)`；700px 以下全屏。使用现有表面、遮罩、圆角和阴影 Token。
- 桌面左侧固定导航，右侧固定标题和关闭按钮，仅正文滚动。移动端使用同一窗口内的页面选择器，不叠加导航弹窗。
- 窗口仅有一个可见标题，不重复品牌、用户信息和正文标题。Parallel Routes 布局持续挂载，section 使用 replace；关闭或后退回到原工作区，直接访问使用中性背景和同一窗口。
- 个人分组包含个人资料、登录与安全；工作区分组包含基本信息、成员管理、积分与充值、操作记录。只读资料不提供虚假编辑入口，成员和操作记录遵循工作区角色权限。
- 供应商连接和模型属于站点后台全局配置，不显示工作区选择器。供应商管理平台、连接凭据及启停，一份连接可供多个模型共用；模型管理能力及三项共享基准价，平台维护 OCR、Embedding 基准价。工作区只设置一个消费倍率，由站点管理员按显式目标管理，不改变管理员会话工作区。
- 工作区设置与后台工作区详情不设置“当前模型”，也不提供模型选择编辑器；站点默认模型只作为问答页面的初始选择，不限制用户使用其他可用模型。
- 模板页面分新模型初始价和平台文档基准价两组。前者只初始化新模型，后者动态用于工作区；待配置、零价与停用分别表达，复用 PolicyTable，允许保存草稿但不自动激活计费。
- 主页、设置、后台复用 `navigation-item` 及导航 Token：40px 行高、13px 字号、18px 图标、10px 间距、6px 圆角；共享选中和焦点态，不使用设置专有竖线。三个侧栏独立组织信息，不创建万能侧栏。
- 未保存输入使用统一内联放弃确认，刷新使用浏览器原生提示；密码不持久化。内容请求使用局部骨架、错误和重试，始终保留导航、标题、关闭入口。
- 工作台内打开设置时，由持久布局立即挂载唯一的设置窗口；拦截路由只提供正文。路由预取用于提速，不能成为显示窗口的前提。冷加载、网络失败及重试仅影响正文，加载中关闭不得被迟到响应重新打开。
- 问答模型列表与发送接口共用可用性判断；停用、价格待配置和服务尚未就绪分别表达，不以笼统的“暂不可选”隐藏原因，也不向普通成员暴露连接详情或内部价格。

## 5. 组件规范

### 站点运营

- 手动积分调整从用户所属工作区或工作区详情进入，复用 `WorkspaceCredits` 与现有 Dialog，
  不新增个人余额。明确工作区共享范围，先填写增加/扣减、整数数量与必填原因，再确认目标和余额。
  失败保留输入，余额变化要求刷新并重新确认；结果不确定只能重试原调整，不静默发起新扣款。
  内部原因与操作者仅在管理员最近调整中显示，普通流水使用“人工入账 / 人工扣减”。
  表单、摘要及调整记录复用 Token，手机控件至少 44px，不嵌套确认弹窗。

- 注册赠送与单条站点公告集中在后台“站点设置”，使用既有后台标题、分区表单、
  未保存确认和版本冲突反馈；不在个人或工作区设置中增加经营配置。
- 注册赠送允许明确填写 0，只影响之后新账号，不把修改配置表现为对既有余额的调整。
- 公告在统一工作台标题栏下方使用紧凑单行入口，长标题省略；正文按需通过已有 Dialog 查看，
  只渲染纯文本。关闭后不重复打扰，侧栏保留查看入口，新公告版本重新提示。
- 不做强制弹窗、不展示配置版本、技术状态或加载说明；读取失败不得阻塞知识库、问答或扩展。
  公告关闭及详情按钮手机至少 44px，详情支持 Escape 与焦点恢复。

### 5.1 按钮

- 主按钮只用于当前区域的主要提交或创建动作。
- 次按钮用于并列的安全操作。
- 危险操作使用语义危险色，并且需要确认或可恢复机制。
- 图标按钮只用于熟悉的单一动作；不熟悉的图标必须有 Tooltip。
- 图标按钮必须有 `aria-label`，文本按钮必须有明确动词。
- 提交期间禁用重复提交，但不隐藏错误原因。

### 5.2 输入、菜单和弹窗

- 所有输入必须有可访问名称和错误反馈。
- Dialog、Popover、Tabs、Tooltip 和菜单优先使用 Radix。
- 弹窗打开后焦点进入合理位置，关闭后回到触发元素。
- `Escape` 关闭安全弹窗；任务进行中可阻止关闭并明确显示忙碌状态。
- 表单失败保留输入，不清空用户已经填写的内容。

### 5.3 状态

每个异步操作至少定义：

- 初始状态
- 加载状态
- 成功状态
- 失败状态
- 空状态
- 禁用状态
- 权限不足状态

加载状态使用真实骨架或明确的加载文案；不使用无法对应后端进度的假百分比。

## 6. 动效规范

### 6.1 动效目标

动效只解决三件事：

1. 表达状态变化。
2. 保持空间关系。
3. 给出及时的操作反馈。

动效不用于：

- 装饰空白区域。
- 无限循环吸引注意。
- 模拟不存在的系统进度。
- 让用户等待动画结束。

### 6.2 动效层级

**生产型动效**用于日常工作：

- Hover、Press、Focus
- Tooltip、Popover、Dropdown
- Dialog、Drawer
- Tab 和筛选切换
- 列表增删和状态更新

**表达型动效**用于重要 AI 反馈：

- Agent 开始执行任务
- Agent 正在检索或调用工具
- 工具调用完成
- 回答完成并出现引用
- 知识库创建完成
- 充值成功
- 重要失败或需要用户介入

### 6.3 动效参数

| 场景 | 时长 | 推荐属性 |
| --- | ---: | --- |
| Hover / Press | 80–120ms | opacity、background、transform |
| Focus / 状态切换 | 120–160ms | border、box-shadow、opacity |
| Tooltip / Popover | 120–180ms | opacity、translate |
| Dialog / Drawer | 200–280ms | opacity、translate、scale |
| 列表进入 | 180–260ms | opacity、translate |
| Agent 状态变化 | 200–320ms | opacity、scale、translate |
| 成功反馈 | 240–420ms | opacity、scale、短距离位移 |

### 6.4 动效实现

- 统一使用 `motion/react`，由根布局提供统一的 `MotionConfig`。
- 默认使用 `easeOut` 或平滑的 cubic-bezier，不使用夸张弹跳。
- 优先动画 `opacity` 和 `transform`，避免造成大面积布局重排。
- 列表使用轻微错峰，最多 4 个条目，不能让长列表逐项等待。
- Agent 状态可以使用轻微呼吸或脉冲，但必须有限时、低对比，并且在完成后停止。
- 流式回答不对每个字符做独立动画；使用稳定的增量渲染和段落级反馈。
- 所有动效支持 `prefers-reduced-motion`，减少为即时切换或极短淡入。
- 动效不得遮挡内容、改变按钮尺寸或造成布局抖动。

## 7. Agent 表达规范

Agent 是知库的重要差异化体验，但表达必须服务于理解：

- 空闲：展示可执行的能力入口，不展示虚假的“在线”状态。
- 准备：说明正在理解问题或规划步骤。
- 检索：说明正在查找相关知识，不显示内部提示词。
- 工具调用：展示工具名称、用途和结果状态。
- 生成：展示回答正在形成，但不模拟真人思考。
- 完成：回答、引用和可执行的后续操作一起出现。
- 失败：说明失败原因，给出重试、缩小范围或换问题的路径。

Agent 的表达型动效必须满足：

- 状态可被文本和辅助技术理解。
- 即使关闭动画，信息仍然完整。
- 不用颜色、闪烁或声音单独表达重要状态。

## 8. 无障碍与响应式

- 核心工作流必须可用键盘完成。
- 所有可交互元素必须有可见或可访问的名称。
- 焦点环不可被 `outline: none` 静默移除。
- 不得只依赖颜色区分状态。
- 移动端优先保证导航、上传、问答、引用查看和弹窗可用。
- 页面不得出现横向滚动；表格在小屏上应采用可读的重排或局部滚动。
- 触控目标不能过小，图标按钮应保持稳定尺寸。
- 系统开启 reduced motion 后，内容顺序和反馈仍然清晰。

## 9. 内容与文案

### 用户任务优先

- 默认只展示任务对象、必要限制、真实进度、结果与下一步。存储厂商、OCR 供应商、内部配置加载、迁移阶段和版本号不作为普通业务窗口的说明文案。
- 上传窗口保留文件选择、格式与大小限制、逐文件进度、处理结果及恢复操作；不展示“原文件存储于某云”“PDF 交由某服务解析”“正在读取文件处理配置”或“关闭窗口不影响传输”等实现和使用说明，也不为这些说明增加阻塞上传的请求。
- 不把所有状态都当成技术信息删除：“正在上传”“正在处理”“已完成”“上传失败，请重试”等真实任务反馈必须保留。错误表达行动，不让普通用户排查存储桶跨域等配置。
- 管理员配置页可以显示正在管理的供应商或存储对象；低频诊断按需查看。必要的隐私、费用或风险告知放在相应政策与确认场景，不堆成业务窗口中的技术段落。
- 每次 UI 修改都人工审查可见文案，判断用户是否需要据此采取行动；无助于任务的实现说明应删除，不改写成另一段技术提示。

### 计费管理表单

- 后台“计费管理”使用“工作区倍率”“平台价格”二级导航，平台价格不展示工作区目标。未选择目标时只展示工作区列表；已选择时展示稳定的对象上下文，使用现有 Dialog 更换管理对象，不将完整选择列表插入编辑正文，也不改变登录会话工作区。
- 模型价格预览覆盖该工作区可见模型，不以消费关联是否存在决定展示范围；每个模型一行比较输入、缓存读取和输出，明确基准价、倍率后价格及实际计量单位。手机重排为带标签条目，不横向撑开页面；未保存倍率统一标记预览。
- 模型可用性和默认标记分别表达；所有站点模型对工作区可见，停用、连接未就绪和价格待配置只影响可用状态，不再提供没有授权分配能力支撑的“发布范围”开关。价格配置完整不代表当前结算已启用缓存计价。预览不写关联、不复制价格、不改变运行时计费。
- 模型管理首页展示供应商名称、平台、可用模型数和启停，详情默认展示模型列表，使用清晰的“模型 / 连接设置”页签。连接凭据只在连接设置管理，不要求填写内部标识；已有模型只显示所属连接入口，不复制凭据表单。
- 新增按“连接供应商 → 选择模型 → 配置并启用”推进，获取失败可手动添加，保留已选项和草稿。模型发现只是候选列表，不等同于调用验证；不自动全部导入。每个模型的能力和价格一起提交，支持批量草稿或校验后启用，不能再要求先保存模型、跳价格、返回启用。
- 添加供应商先选择调用类型：OpenAI Chat Completions 或 OpenAI Responses，再显示平台和连接表单，不预选或按地址猜测。列表及连接设置明确当前类型；接口路径只在管理员配置场景展示。切换类型保留地址、凭据和草稿，不兼容时定位到模型配置，不自动回退另一种接口。
- 模型详情使用“模型设置 / 价格”页签及统一的保存模型操作；切换页签有未保存确认。价格沿用 PolicyTable 和人民币定价助手，高级参数与诊断按需展开。只有精确匹配且注明官方依据的模型才提供可确认应用的能力预设，不以名称模糊推断容量。页签必须有清晰边界、选中态和键盘焦点，不使用超长弹窗或嵌套卡片。
- 供应商及平台基准价复用 PolicyTable；工作区页面只有倍率编辑和只读有效价格表，不保留逐项价格编辑。倍率支持 0.01–100.00、最多两位小数，默认 1.00。
- 价格缺失显示“待配置”和空输入，不能渲染成零价；免费必须由管理员明确填写 0。
- 基准价完整保存，倍率独立保存；保留版本、来源、局部错误、重试和未保存提示。倍率价格预览展示精确小数，不把每单位价格取整成实际扣分；旧模式下清楚区分“当前旧规则”和“待启用的共享价格预览”。
- 模型基准价保存说明新调用将使用新价格、既有消费不变；已有消费关联数仅作使用信息，不作为改价影响范围。工作区计费页聚焦倍率与当前有效价格预览，不展示迁移价差或旧价格明细。
- 普通用户只显示余额、实际使用量与待结算积分及充值引导，不公开内部价格、规则快照或公式。
- 价格输入使用 `--form-font-size`（13px）、标签使用 `--form-label-size`（12px），桌面控件至少 40px、手机至少 44px；间距、圆角和警告表面复用对应 Token。
- 计量单位作为数值旁的只读后缀，避免将固定的 Token、页数语义呈现为自由文本输入。价格表保留原单位数据及保存协议，不改变计价方式。
- 人民币定价助手只从可编辑的 PolicyTable 进入，复用现有 Dialog。按每单位成本、目标利润、费用分摊和可调支付费率计算；最优惠真实充值套餐作为保守兑换依据，不虚构兑换比例。显示整数积分对应售价、取整增量、倍率后的收入与利润及亏损警告；单位变化明确提示，不能自动放大单位。应用仅修改当前价格表单，继续使用原保存和版本冲突流程；试算不修改工作区倍率、支付渠道费率或真实价格。公式收进可展开的“计算依据”，不堆说明段落。
- 表头与行使用同一套列定义；窄容器统一切为带可见标签的两列表单，不能保留错位的桌面表头，也不能为模板保留空的操作列。
- 配置缺失使用警告图标、文字与语义色，未保存和版本信息分层呈现；模板保存有独立操作区，单行保存复用 Tooltip。待结算属于可处理的余额状态，不复用表单报错样式。
- 手机后台复用同一组导航链接，排列为可横向滚动的紧凑导航，不在正文前铺开多行菜单；导航本身可滚动，页面不得横向溢出。

- 使用直接、具体、可行动的中文。
- 错误信息说明发生了什么、用户可以做什么。
- 不向普通用户暴露 `local`、Docker、容器、服务端口、向量维度等部署细节。
- “正在处理”“已完成”“无法回答”“需要权限”等状态必须与真实后端状态一致。
- 不使用夸张的 AI 拟人化文案掩盖系统限制。

## 10. 开发验收清单

每次涉及 UI、UX 或动效的改动，至少检查：

- 是否复用了现有 Radix、Lucide 和 Motion 入口。
- 是否新增了重复依赖或重复组件实现。
- 是否定义了加载、成功、失败、空、禁用和无权限状态。
- 是否验证了键盘焦点、Escape 关闭和 Tooltip。
- 是否验证了 `prefers-reduced-motion`。
- 是否在 1440px 桌面和 390px 移动宽度检查布局。
- 是否没有横向溢出、布局抖动和文字遮挡。
- 是否保留真实 API 行为，没有虚构状态或进度。
- 是否逐项审查可见文案，删除与任务无关的技术实现、部署阶段和界面使用说明，并对已清理文案添加回归断言。
- 是否执行 `npm run build`。
- 涉及关键流程时，是否用 Playwright 验证真实浏览器行为。

## 11. 参考基线

本规范吸收以下成熟方案的原则，但不做品牌或页面的像素复制：

- Radix Primitives：无障碍交互基元。
- shadcn/ui：可控的组件源码与组合方式。
- Radix Colors：语义色阶和明暗主题基础。
- Lucide：统一图标系统。
- Motion：React 动画与 reduced-motion 支持。
- Carbon Design System：生产型动效与表达型动效的区分。
- Atlassian Design System：时长、缓动和属性的动效建模。
- WCAG 2.2：键盘、对比度、焦点和动画可访问性要求。
