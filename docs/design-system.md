# 知库设计系统规范

- 状态：已确认，作为前端开发约束
- 适用范围：知库 Web 前端、知识库工作台、知识问答、Agent 状态、账号与计费界面
- 关联 Issue：[Issue #10](https://github.com/pengGgxp/rag/issues/10)、[Issue #19](https://github.com/pengGgxp/rag/issues/19)
- 最后更新：2026-10-24

## 1. 产品气质

知库是一个长期使用的知识工作空间，不是营销落地页，也不是后端调试面板。
界面应同时具备两种气质：

1. **Calm Knowledge Workspace**：文档、知识库和配置界面稳定、清晰、耐用。
2. **Developer Intelligence**：检索详情和 Agent 工具调用保留技术产品的密度与可观察性；系统级诊断不作为普通用户导航入口。

表达型动效只用于 Agent 的关键状态和重要反馈，不让整个工作台变成动画展示页。

### 1.1 设计原则

- **先表达状态，再表达装饰**：用户始终能知道正在发生什么、是否完成、下一步能做什么。
- **信息密度服务于工作**：优先支持扫描、比较、定位和恢复操作。
- **复杂信息按需展开**：默认展示结论，引用、Trace、工具调用和诊断信息逐层展开。
- **真实状态优先**：不制造虚假的进度、在线状态、模型状态或处理结果。
- **可恢复**：错误保留用户输入，危险操作明确，删除优先采用可恢复的回收站语义。
- **视觉统一但不单调**：中性表面承载内容，Cobalt 建立产品识别，Indigo 表达 Agent，Cyan 表达引用与检索，语义色只承担语义。

## 2. 技术基线

以下库是项目的唯一默认入口，不为相同职责引入第二套方案：

| 能力 | 规范入口 | 约束 |
| --- | --- | --- |
| 无障碍交互基元 | Radix Primitives | Dialog、Tabs、Tooltip、Popover、Menu 等优先复用 |
| 可控组件源码 | shadcn/ui 风格组件 | 组件源码放在项目内，允许按产品需要修改 |
| 动画 | `motion/react` | 统一由 Motion 实现组件和状态动效 |
| 图标 | Lucide | 不混用其他图标库，不手写重复图标 |
| 跨页面 UI 状态 | Zustand | 仅管理真正跨视图的 UI 状态 |
| 可调面板 | `react-resizable-panels` | 只有出现真实可调面板需求时才引入 |
| 拖拽 | `dnd-kit` | 只有出现真实拖拽工作流时才引入 |
| 浏览器验收 | Playwright CLI | 桌面、移动、键盘和关键业务流必须可复验 |

### 2.1 依赖规则

- 一个职责只保留一个默认依赖。
- 不为了一个小交互引入完整组件库。
- 不复制组件库的内部实现到业务组件中。
- 业务组件可以组合基础组件，但不得绕过 Radix 的焦点、键盘和关闭行为。
- 新增依赖前说明它解决的真实问题、替代方案和移除成本。

## 3. 视觉 Token

所有颜色、间距、圆角、阴影和动效参数都应先定义为语义 Token，再在组件中使用。
禁止在业务 JSX 中散落不可解释的颜色值和时长值。

### 3.1 颜色层级

推荐建立以下语义层：

```css
--background
--surface
--surface-raised
--surface-muted
--text-primary
--text-secondary
--text-tertiary
--border-subtle
--border-default
--brand
--brand-foreground
--interactive
--interactive-hover
--focus-ring
--success
--warning
--danger
--info
```

颜色使用规则：

- 页面背景和工作区表面以中性灰白为主。
- **Cobalt** 是产品主色，用于主按钮、当前导航、选中状态和主要交互。
- **Indigo** 只用于 Agent、模型执行和表达型 AI 状态，不作为全局背景。
- **Cyan** 用于引用、检索、来源链接和知识定位。
- **Emerald/绿色** 只表示成功、已完成和健康状态，不再承担品牌色。
- 红色表示危险或失败，Amber 表示等待或警告，不能作为普通装饰。
- 文本和边框必须满足可读性对比度。
- 暗色模式如果实现，必须复用同一套语义 Token，不单独写一套业务颜色。

### 3.1.1 已确认主题

```css
/* 产品主色：Cobalt */
--brand: #2563eb;
--brand-hover: #1d4ed8;
--brand-soft: #eff6ff;

/* Agent 表达：Indigo */
--agent: #4f46e5;
--agent-soft: #eef2ff;

/* 引用与检索：Cyan */
--reference: #0891b2;
--reference-soft: #ecfeff;

/* 中性工作台 */
--background: #f8fafc;
--surface: #ffffff;
--surface-muted: #f1f5f9;
--text-primary: #172033;
--text-secondary: #64748b;
--border-default: #e2e8f0;
--focus-ring: #2563eb;

/* 仅用于真实语义 */
--success: #16a34a;
--warning: #d97706;
--danger: #dc2626;
```

主题组合规则：

- 页面大面积使用 `background`、`surface` 和 `surface-muted`，不铺品牌色。
- 同一视图只允许一个主操作色；Agent 状态和引用可以使用各自的辅助色。
- 不使用蓝紫渐变、整页紫色背景或大面积高饱和色块。
- 状态颜色必须同时有文字、图标或结构表达，不能只靠颜色区分。

### 3.2 排版

- 中文优先使用系统无衬线字体，保留 `Microsoft YaHei` 等中文回退。
- 页面标题只在真正的页面入口使用大字号。
- 工作台、表格、侧栏和弹窗使用紧凑标题，不使用营销式超大标题。
- 正文行高优先保证阅读，表格和元数据可以更紧凑。
- `letter-spacing` 默认保持为 `0`，不使用负字距挤压中文。
- 数字、时间、积分和模型参数使用等宽数字或稳定的数字对齐方式。

### 3.3 几何与表面

- 默认圆角为 6px 或 8px；仅在现有组件行为确有需要时使用更大圆角。
- 页面分区使用整宽布局或约束容器，不把每个区域都包成卡片。
- 不允许卡片套卡片。
- 卡片只用于重复条目、弹窗和确实需要边界的工具。
- 阴影应表达层级，不用于制造装饰性浮层。
- 不使用渐变球、光晕块、玻璃拟态噪声作为常规背景。

## 4. 页面与信息架构

### 4.1 工作台

- 左侧导航负责知识库、问答和扩展入口。
- 主区域负责当前任务，不同时展示互相竞争的多个主入口。
- 面包屑只表达当前层级，不重复完整导航。
- 页面标题下方优先放当前状态、范围和关键操作。
- 主要操作使用一个明确的主按钮，其余操作降级为次按钮或图标按钮。

### 4.2 知识库与文档

- 知识库列表优先支持搜索、选择和进入。
- 文档列表以文件名、处理状态、版本和更新时间为核心。
- 处理中、失败、已删除和已归档必须有清晰且可读的状态。
- 原文预览、引用详情和版本信息按需展开。
- 删除、归档和恢复必须给出明确反馈，不使用静默状态变化。

### 4.3 问答与 Agent

- 回答正文是主内容，引用、回答详情和 Trace 是可展开的辅助层。
- Agent 的思考、检索、工具调用和完成状态要能被用户理解，但不展示无意义的内部日志。
- 工具调用展示“正在做什么”和“结果是什么”，参数和原始响应按需查看。
- 没有证据时显示明确拒答，不用动画掩盖缺少证据。
- Agent 失败时保留已生成内容和可恢复操作。

## 5. 组件规范

### 5.1 按钮

- 主按钮只用于当前区域的主要提交或创建动作。
- 次按钮用于并列的安全操作。
- 危险操作使用语义危险色，并且需要确认或可恢复机制。
- 图标按钮只用于熟悉的单一动作；不熟悉的图标必须有 Tooltip。
- 图标按钮必须有 `aria-label`，文本按钮必须有明确动词。
- 提交期间禁用重复提交，但不隐藏错误原因。

### 5.2 输入、菜单和弹窗

- 所有输入必须有可访问名称和错误反馈。
- Dialog、Popover、Tabs、Tooltip 和菜单优先使用 Radix。
- 弹窗打开后焦点进入合理位置，关闭后回到触发元素。
- `Escape` 关闭安全弹窗；任务进行中可阻止关闭并明确显示忙碌状态。
- 表单失败保留输入，不清空用户已经填写的内容。

### 5.3 状态

每个异步操作至少定义：

- 初始状态
- 加载状态
- 成功状态
- 失败状态
- 空状态
- 禁用状态
- 权限不足状态

加载状态使用真实骨架或明确的加载文案；不使用无法对应后端进度的假百分比。

## 6. 动效规范

### 6.1 动效目标

动效只解决三件事：

1. 表达状态变化。
2. 保持空间关系。
3. 给出及时的操作反馈。

动效不用于：

- 装饰空白区域。
- 无限循环吸引注意。
- 模拟不存在的系统进度。
- 让用户等待动画结束。

### 6.2 动效层级

**生产型动效**用于日常工作：

- Hover、Press、Focus
- Tooltip、Popover、Dropdown
- Dialog、Drawer
- Tab 和筛选切换
- 列表增删和状态更新

**表达型动效**用于重要 AI 反馈：

- Agent 开始执行任务
- Agent 正在检索或调用工具
- 工具调用完成
- 回答完成并出现引用
- 知识库创建完成
- 充值成功
- 重要失败或需要用户介入

### 6.3 动效参数

| 场景 | 时长 | 推荐属性 |
| --- | ---: | --- |
| Hover / Press | 80–120ms | opacity、background、transform |
| Focus / 状态切换 | 120–160ms | border、box-shadow、opacity |
| Tooltip / Popover | 120–180ms | opacity、translate |
| Dialog / Drawer | 200–280ms | opacity、translate、scale |
| 列表进入 | 180–260ms | opacity、translate |
| Agent 状态变化 | 200–320ms | opacity、scale、translate |
| 成功反馈 | 240–420ms | opacity、scale、短距离位移 |

### 6.4 动效实现

- 统一使用 `motion/react`，由根布局提供统一的 `MotionConfig`。
- 默认使用 `easeOut` 或平滑的 cubic-bezier，不使用夸张弹跳。
- 优先动画 `opacity` 和 `transform`，避免造成大面积布局重排。
- 列表使用轻微错峰，最多 4 个条目，不能让长列表逐项等待。
- Agent 状态可以使用轻微呼吸或脉冲，但必须有限时、低对比，并且在完成后停止。
- 流式回答不对每个字符做独立动画；使用稳定的增量渲染和段落级反馈。
- 所有动效支持 `prefers-reduced-motion`，减少为即时切换或极短淡入。
- 动效不得遮挡内容、改变按钮尺寸或造成布局抖动。

## 7. Agent 表达规范

Agent 是知库的重要差异化体验，但表达必须服务于理解：

- 空闲：展示可执行的能力入口，不展示虚假的“在线”状态。
- 准备：说明正在理解问题或规划步骤。
- 检索：说明正在查找相关知识，不显示内部提示词。
- 工具调用：展示工具名称、用途和结果状态。
- 生成：展示回答正在形成，但不模拟真人思考。
- 完成：回答、引用和可执行的后续操作一起出现。
- 失败：说明失败原因，给出重试、缩小范围或换问题的路径。

Agent 的表达型动效必须满足：

- 状态可被文本和辅助技术理解。
- 即使关闭动画，信息仍然完整。
- 不用颜色、闪烁或声音单独表达重要状态。

## 8. 无障碍与响应式

- 核心工作流必须可用键盘完成。
- 所有可交互元素必须有可见或可访问的名称。
- 焦点环不可被 `outline: none` 静默移除。
- 不得只依赖颜色区分状态。
- 移动端优先保证导航、上传、问答、引用查看和弹窗可用。
- 页面不得出现横向滚动；表格在小屏上应采用可读的重排或局部滚动。
- 触控目标不能过小，图标按钮应保持稳定尺寸。
- 系统开启 reduced motion 后，内容顺序和反馈仍然清晰。

## 9. 内容与文案

- 使用直接、具体、可行动的中文。
- 错误信息说明发生了什么、用户可以做什么。
- 不向普通用户暴露 `local`、Docker、容器、服务端口、向量维度等部署细节。
- “正在处理”“已完成”“无法回答”“需要权限”等状态必须与真实后端状态一致。
- 不使用夸张的 AI 拟人化文案掩盖系统限制。

## 10. 开发验收清单

每次涉及 UI、UX 或动效的改动，至少检查：

- 是否复用了现有 Radix、Lucide 和 Motion 入口。
- 是否新增了重复依赖或重复组件实现。
- 是否定义了加载、成功、失败、空、禁用和无权限状态。
- 是否验证了键盘焦点、Escape 关闭和 Tooltip。
- 是否验证了 `prefers-reduced-motion`。
- 是否在 1440px 桌面和 390px 移动宽度检查布局。
- 是否没有横向溢出、布局抖动和文字遮挡。
- 是否保留真实 API 行为，没有虚构状态或进度。
- 是否执行 `npm run build`。
- 涉及关键流程时，是否用 Playwright 验证真实浏览器行为。

## 11. 参考基线

本规范吸收以下成熟方案的原则，但不做品牌或页面的像素复制：

- Radix Primitives：无障碍交互基元。
- shadcn/ui：可控的组件源码与组合方式。
- Radix Colors：语义色阶和明暗主题基础。
- Lucide：统一图标系统。
- Motion：React 动画与 reduced-motion 支持。
- Carbon Design System：生产型动效与表达型动效的区分。
- Atlassian Design System：时长、缓动和属性的动效建模。
- WCAG 2.2：键盘、对比度、焦点和动画可访问性要求。
