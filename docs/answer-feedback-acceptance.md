# 问答反馈闭环

## 目标

用户可以对已完成的回答点赞或点踩。点踩时可选择问题类型并补充说明，反馈必须关联工作区、会话、消息和本轮检索轨迹，供后续质量分析使用。

## 不包含

本次不实现自动模型评估、反馈报表、奖励模型和自动改写知识库。反馈不改变历史回答和引用内容。

## 验收标准

- 只有回答消息的创建者可以提交或修改自己的反馈。
- 同一用户对同一回答只有一条反馈，重复提交幂等更新。
- 点赞直接保存；点踩至少选择一个问题类型，可选填写说明。
- 反馈 API 校验会话、消息、工作区和知识库权限，不能跨工作区猜 ID。
- 删除或失权后不能读取或修改原会话反馈。
- 前端在回答操作区显示点赞、点踩状态，点踩使用紧凑弹窗。
- 后端专项测试、前端构建和真实浏览器交互通过。

## 实现与验收结果

2026-10-20 已完成：

- `POST /feedback` 原子新增或更新反馈，`DELETE /feedback/{message_id}` 幂等撤销。
- 消息详情携带当前反馈，刷新后恢复赞/踩状态；点踩详情可重新打开修改。
- 新增 `answer_feedback` 表及迁移 `0008_add_answer_feedback`。消息关联会话和本轮 traces，不复制问题或原文到反馈表。
- 权限检查沿用工作区、会话归属和知识库可见性。未完成回答、用户消息、已删除会话均拒绝新增反馈。
- 52 项后端测试通过，包含原有 RAG/认证回归及新增的反馈校验、重复提交、删除和失权测试。
- 前端生产构建、Docker 构建和实际 PostgreSQL 迁移通过。
- 真实浏览器验证点赞、刷新恢复、点踩分类/说明、修改、取消与撤销。390px 视口页面宽度为 390px，弹窗宽度为 366px。
- 验收账号、知识库、会话和检索轨迹已清理；原有 7 个知识库、9 个文档、1 个会话保留。
