# Issue #36: Agent 模型用量与缓存计费

## 目标与边界

每次实际模型调用记录普通输入、缓存读取和输出；工具定义、Skill 内容及工具结果作为模型输入、工具参数作为模型输出，统一使用 API usage，不另设 MCP/Skill 按次收费。

各轮费用按比例精确累加，请求结束四舍五入保留四位小数（Issue #57 更新），不再向上取整为整数。取消/失败保留已确认消费，余额不足保存待结算，下次模型请求前先结清。OCR、Embedding 同样按实际用量比例结算，充值及历史账单保持原样。

## 当前任务（2026-10-30）

目标：完成 #36 的正式启用与真实缓存账单验收。范围为请求级模型结算、启用校验、回归测试与部署；另按用户明确确认，将 gpt-6-astra 的输出 1001.001 积分和特价 deepseek-v4.1-flash 的输出 211 积分从每千 Token 改为每百万 Token。积分数值、其他单价、倍率及历史消费保持原样，不新增迁移界面。

验收：普通输入与缓存不重叠，各轮精确费用汇总后只保留一次四位小数；取消、失败、恢复、重复结算及待结算可靠；共享计价下校验全部启用模型而非废弃的工作区 active 选择。执行后端回归、独立 PostgreSQL 并发验证及真实 HTTP/SSE 缓存消费与账单核对。

```text
普通输入 = 上游输入总量 - 可信缓存读取量
请求积分 = round_half_up_4(工作区倍率 × Σ各轮(
  普通输入 × 输入单价 / 输入计价单位
  + 缓存读取 × 缓存单价 / 缓存计价单位
  + 输出 × 输出单价 / 输出计价单位))
```

缺失或异常缓存字段不估算折扣，使用有效输入总量计普通输入并保留诊断。推理 Token 已包含在输出总量时不重复加计。成功响应缺少 usage 时保留明确标记的估算；失败且没有可靠用量时不估算扣费。

## 配置与发布

模型三项基准价由站点模型管理，工作区使用共享价格和独立倍率，不再复制工作区价格。模板中的模型价格仅初始化新模型，不作运行时回退；OCR、Embedding 使用平台文档价格。缺失价格不自动填零。

启用前暂停新付费请求、排空模型与手动压缩调用，核对所有启用连接下启用模型的三项价格。没有工作区关联的可选模型也必须检查；不依赖工作区 active 模型或初始价模板。新增表保留请求/调用/快照和结算状态，不记录提示词正文或秘密。回滚保留新增数据与待结算处理。

## 管理员配置与启用

1. `/admin/models/{id}` 配置模型的普通输入、缓存读取、输出三项基准价；未填写与明确零价不同。逐项检查单价的实际 Token 单位，不自动更改商业价格。
2. `/admin/pricing?workspace=<id>` 查看工作区倍率及有效价格；不存在需要复制的工作区模型价格。
3. 排空调用、暂停新请求后，在服务器检查并切换：

```sh
docker compose exec -T api python -m app.manage model-billing status
docker compose exec -T api python -m app.manage model-billing enable
```

启用命令检查启用模型的完整价格及未结束请求，价格不完整则拒绝。启用后每个请求仍在调用上游前校验价格与状态。站点管理员可定位缺失模型；普通用户得到可执行的服务错误。开发版完成验收后直接启用，不再保留“已部署但未启用”作为交付状态。

4. 使用隔离账号执行有限真实验收（最多三次调用，保留账单，结束后停用账号并撤销会话）：

```sh
PYTHONPATH=/app python /verify/verify-cache-billing.py --run-live --model qwen3.8-max-0902
```

验证实际缓存命中、普通输入与缓存总量、三项计价、精确汇总、单笔扣款与重放幂等。未观察到命中则验收失败，不用模拟替代。

`model-billing disable` 仅在没有运行中请求和待结算时允许；否则必须先排空/充值并结清。不能通过切回旧 API 绕过待结算。回滚 UI 可以保留新 API；涉及 API 回滚时保留新增数据结构及恢复/待结算处理，不执行破坏性迁移。
