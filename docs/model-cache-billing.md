# Issue #36: Agent 模型用量与缓存计费

## 目标与边界

每次实际模型调用记录普通输入、缓存读取和输出；工具定义、Skill 内容及工具结果作为模型输入、工具参数作为模型输出，统一使用 API usage，不另设 MCP/Skill 按次收费。

各轮费用按比例精确累加，请求结束四舍五入保留四位小数（Issue #57 更新），不再向上取整为整数。取消/失败保留已确认消费，余额不足保存待结算，下次模型请求前先结清。OCR、Embedding 同样按实际用量比例结算，充值及历史账单保持原样。此精度修复不启用缓存计费开关。

## 配置与发布

已有工作区及供应商缺失缓存价格时不自动填价。新工作区复制管理员维护的模型价格模板，随后独立管理。模板变更不覆盖历史配置。默认只发布配置能力，新结算由数据库开关控制，不修改 .env。

模板、在用工作区及供应商价格补齐后，排空调用再通过服务器命令启用；未配置时不代填价格。新增表保留请求/调用/快照和结算状态，不记录提示词正文或秘密。回滚保留新增数据与待结算处理。

## 验收

缓存字段归一化、流式尾包、异常及估算、多轮工具、取消/失败/断线/恢复、并发幂等、最大余数分配、待结算与模板隔离均需测试。执行 PostgreSQL 迁移和并发测试、前端构建、1440px/390px 浏览器验收及 diff 检查。真实缓存命中未确认或必要价格未配置时不关闭 Issue #36。

按用量采集与持久化、请求级结算、后台价格模板三个 Conventional Commits 提交，部署 API/Web，保留数据库、Redis、存储及 Worker。

## 管理员配置与启用

1. `/admin/pricing/template` 完整保存新工作区的普通输入、缓存读取、输出价格；未填写与明确零价不同，模板按版本校验并发修改。
2. `/admin/pricing?workspace=<id>` 逐个补齐已有工作区环境模型及供应商的三项价格。没有配置的缓存项显示“待配置”，读取不会插入零价。新供应商复制当前工作区价格，不回写工作区或模板。
3. 排空调用、暂停新请求后，在服务器检查并切换：

```sh
docker compose exec -T api python -m app.manage model-billing status
docker compose exec -T api python -m app.manage model-billing enable
```

启用命令检查完整模板、各工作区正在使用的计价范围及未结束请求；价格不完整则拒绝。未启用期间仍使用原结算逻辑。启用后缺少任意三项价格会在上游调用前拒绝；普通用户只看到服务暂不可用，站点管理员在计费表单查看缺失项。新增工作区在创建事务内复制模板及来源版本，模板缺失不阻止注册，但启用新结算后不可请求模型。

`model-billing disable` 仅在没有运行中请求和待结算时允许；否则必须先排空/充值并结清。不能通过切回旧 API 绕过待结算。回滚 UI 可以保留新 API；涉及 API 回滚时保留新增数据结构及恢复/待结算处理，不执行破坏性迁移。

## 组件边界

`PolicyTable` 扩展原有价格行，供工作区规则和模板使用；仅负责字段、可访问名称和按行保存槽，不请求业务数据。模板完整保存、版本冲突、工作区目标与权限仍由各自页面负责。`AdminChangesBoundary` 复用现有内联放弃提示的交互，补齐后台跨页面导航及刷新保护；工作区选择继续复用原来的确认逻辑。表单不新增依赖，不引入第二套导航。
