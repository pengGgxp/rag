# Issue #36: Agent 模型用量与缓存计费

## 目标与边界

每次实际模型调用记录普通输入、缓存读取和输出；工具定义、Skill 内容及工具结果作为模型输入、工具参数作为模型输出，统一使用 API usage，不另设 MCP/Skill 按次收费。

各轮费用按比例精确累加，请求结束只向上取整一次。取消/失败保留已确认消费，余额不足保存待结算，下次模型请求前先结清。OCR、Embedding、充值及历史账单保持原样。

## 配置与发布

已有工作区及供应商缺失缓存价格时不自动填价。新工作区复制管理员维护的模型价格模板，随后独立管理。模板变更不覆盖历史配置。默认只发布配置能力，新结算由数据库开关控制，不修改 .env。

模板、在用工作区及供应商价格补齐后，排空调用再通过服务器命令启用；未配置时不代填价格。新增表保留请求/调用/快照和结算状态，不记录提示词正文或秘密。回滚保留新增数据与待结算处理。

## 验收

缓存字段归一化、流式尾包、异常及估算、多轮工具、取消/失败/断线/恢复、并发幂等、最大余数分配、待结算与模板隔离均需测试。执行 PostgreSQL 迁移和并发测试、前端构建、1440px/390px 浏览器验收及 diff 检查。真实缓存命中未确认或必要价格未配置时不关闭 Issue #36。

按用量采集与持久化、请求级结算、后台价格模板三个 Conventional Commits 提交，部署 API/Web，保留数据库、Redis、存储及 Worker。
