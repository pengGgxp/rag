# 积分与用量验收

## 产品边界

平台统一配置 Embedding 和 LLM，用户不管理模型 API Key。工作区通过积分使用问答能力。
2026-10-22 起，充值改为支付 FM 验签支付到账，详见 [充值验收](recharge-acceptance.md)。
工作区管理员也是客户，不再拥有任意增加积分的权限。

## 验收标准

- 新工作区拥有明确的积分余额和初始流水。
- `GET /usage` 只返回当前工作区的余额、累计获得、累计消耗和最近流水。
- 工作区成员可以通过支付充值，订单仅本人可见，积分归所在工作区共享。
- 客户不能直接增加积分；重复支付通知不能重复增加余额。
- 请求开始前只建立可配置的内部授权预留；余额不足时不创建模型请求。
- LLM 按每轮真实或估算的输入/输出 Token 结算，规则快照随用量事件保存。
- OCR 按解析页数、Embedding 按输入 Token 结算；MCP 和 Skill 不单独收费，其结果只会进入后续模型上下文。
- 成功回答保留按实际用量生成的扣费流水。
- 失败、取消和中断会释放内部授权预留，不产生固定假扣费。
- 释放操作幂等，重复回收不会增加余额。
- 并发扣费在数据库锁下执行，余额不能变成负数。
- 所有积分流水带工作区、操作者、类型、余额快照和幂等引用。
- 工作区管理员可以通过 `/usage/policies` 管理内部计量规则和版本；普通用户无权读取或修改规则。

## 当前明确不包含

- 订阅套餐、发票和自动续费
- 用户 API Key 管理
- 用户端不展示单价、公式或模型供应商成本，只展示余额、累计消耗和按能力汇总的使用量。
