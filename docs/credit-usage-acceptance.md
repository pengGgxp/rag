# 积分与用量验收

## 产品边界

平台统一配置 Embedding 和 LLM，用户不管理模型 API Key。工作区通过积分使用问答能力。
2026-10-22 起，充值改为支付 FM 验签支付到账，详见 [充值验收](recharge-acceptance.md)。
工作区管理员也是客户，不再拥有任意增加积分的权限。

## 验收标准

- 新工作区拥有明确的积分余额和初始流水。
- `GET /usage` 只返回当前工作区的余额、累计获得、累计消耗和最近流水。
- 工作区成员可以通过支付充值，订单仅本人可见，积分归所在工作区共享。
- 客户不能直接增加积分；重复支付通知不能重复增加余额。
- 问答开始前预扣固定额度；余额不足时不创建模型请求。
- 成功回答保留扣费流水。
- 拒答、失败、取消和中断会释放预扣额度。
- 释放操作幂等，重复回收不会增加余额。
- 并发扣费在数据库锁下执行，余额不能变成负数。
- 所有积分流水带工作区、操作者、类型、余额快照和幂等引用。

## 当前明确不包含

- 订阅套餐、发票和自动续费
- 用户 API Key 管理
- 按供应商实时 token 成本结算
