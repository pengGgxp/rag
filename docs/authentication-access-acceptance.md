# 登录与访问控制

## 目标与范围

让用户通过站内账号或配置的 OIDC 服务登录，在自己的工作区使用知识库和问答。
支持退出、邮件找回密码、账号关联、工作区切换、成员角色和知识库访问范围。
对文档、任务、检索、引用、轨迹、会话和导出统一执行服务器端权限检查。

不包含企业组织同步、计费、MFA、复杂策略引擎和公开分享。
OAuth/SMTP 的实际联调依赖部署者提供服务凭据，不用假登录或明文返回重置令牌代替。

## 数据与权限决策

- 新增用户、工作区、成员、登录会话、外部身份和知识库授权表，保留原有资料。
- 普通注册创建独立工作区，不能读取已有匿名数据。
- 旧数据迁入保留工作区，通过服务器端初始化口令由管理员接管。
- 角色为管理员、编辑者、只读成员；知识库默认对工作区可见，可改为指定成员可见。
- 对话归创建者私有。访问历史、生成、导出时重新检查知识库权限；失权后不返回历史正文或引用快照。
- 会话使用随机不透明 HttpOnly Cookie，数据库仅保存会话令牌摘要；状态变更检查来源和 CSRF。
- OAuth 采用 OIDC 的授权码流程、state、nonce 和 PKCE，不按相同邮箱静默合并账号。

## 验收标准与验证方式

- 真实浏览器完成注册、登录、刷新恢复、退出与账号设置，桌面/手机无布局溢出。
- 未登录的数据 API 返回 401；跨工作区、跨会话猜测 ID 不能读取数据。
- 只读成员无法修改文档/知识库；受限知识库及其任务、轨迹不可越权读取。
- 移除成员或授权后，历史会话、导出和后续生成立即拒绝；进行中的流在权限复查时终止。
- 重置密码令牌有时效、一次性消费，重置后撤销全部登录会话。
- 无 OAuth/邮件配置时界面如实呈现可用入口；OAuth 错误 state 不建立会话。
- 执行后端回归、权限专项测试、前端生产构建和真实浏览器验证。

## 本地 Docker 配置

1. 复制 `.env.example` 为 `.env`，设置 `AUTH_SECRET_KEY` 为至少 32 个字符的随机值。
2. `docker compose up -d --build` 会自动执行数据库迁移。
3. 旧资料首次接管前，在 API 容器执行 `docker compose exec api python -m app.manage bootstrap`，把一次性口令填入“管理员初始化”。
4. OIDC 登录需要填写 `OIDC_METADATA_URL`、`OIDC_CLIENT_ID`、`OIDC_CLIENT_SECRET`，并把回调地址配置为 `http://localhost:8000/auth/oauth/callback`。
5. 找回密码需要配置 SMTP；未配置时不会显示“忘记密码”，也不会把令牌返回给浏览器。

`AUTH_COOKIE_SECURE=false` 只适用于本地 HTTP。部署到 HTTPS 时必须改为 `true`，并同步设置真实的 `FRONTEND_URL` 和 `API_PUBLIC_URL`。
