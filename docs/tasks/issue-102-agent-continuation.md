# Issue #102：资料变化与 Agent 续接

## 目标与范围

资料导入、处理、改名、删除和工具局部失败不应使整个会话失效。记忆负责保留任务背景，计划只记录进展，工具负责观察当前资源和执行当前授权操作，模型根据真实结果决定下一步。

本次从 `f22af8b1d8fa4c2ce5cf927371487b788994adb9` 的独立 worktree 开发，按已确认的源码审查范围同时修复续接、参数纠错、环境读取、错误反馈、结果预算和真实容量恢复，并加入可选计划工具。没有增加固定重试流程、历史撤回依赖图、全局权限 epoch 或工具全面并行；运行中追加消息另议。

## 实现与取舍

| 层 | 实现 | 保留的边界 |
| --- | --- | --- |
| 记忆 | 目录状态退出 `scope_digest`；健康旧窗口更新退役指纹并继续 | 会话归属、登录状态、加密校验、图片快照、checkpoint、工具配对、锁和修订 CAS |
| 计划 | 可选 `update_plan`，compact 显式保留当前进展 | 只维护步骤和状态，不替代模型决策或业务授权 |
| 工具 | 每次先登记执行，再保存加密完整回执和模型投影 | 已知成功、未执行、不确定分别记录；不自动重放副作用 |
| 环境观察 | Skill 提示不刷新整个目录，不隐式恢复全工作区文件操作 | 涉及未完成操作的目标仍受保护，维护恢复机制保留 |
| 局部错误 | 坏 JSON 参数和业务 HTTP 错误回给模型，保留脱敏实际原因 | 缺调用标识、重复 ID、会话鉴权失败等真正协议或身份故障仍失败 |
| 输出 | 完整回执与有限模型投影分开，结果及历史可分页读取 | 检索保留完整 chunk，当前权限、删除、活动版本和引用校验继续执行 |
| 容量 | 明确结构化容量拒绝时，有界 compact 后只重试当前模型步骤一次 | 普通 400、网络失败及结果不确定不触发容量重试；不重跑工具 |

工具正文、工具图片及摘要中的事实是历史观察。本次保留这些记忆，不承诺撤回模型已经见过的事实，也不因为资料变化清退整个混合摘要。历史观察不能自动变成当前证据或权限；新工具仍查当前状态，引用仍校验版本与可见性。

浏览器验收额外发现：手动 compact 准入事务持有锁时，另一个 Session 的 Skill 摘要全目录刷新会等待工作区写锁，导致请求互等。摘要改为只读已有索引中的候选；已知 manifest 仍读取当前元数据与正文，新路径通过正常导入或显式目录刷新进入索引。没有引入新缓存或目录同步架构。

## 数据与恢复

迁移 `0071_agent_tool_executions` 接在 `0070_workspace_file_operations` 后，新增独立工具执行表。主键由模型项 ID 与 call_id 派生；记录所属会话、请求、状态和加密完整结果，随会话级联删除。新表不复制凭据，不修改原始聊天。

续接先读取已保存回执；缺结果时只查询已有本地知识库、MCP、云命令业务回执。执行已开始但无确定回执时告知模型结果不确定；不能声称取消等于回滚。并发准入由会话锁串行，避免同一调用重复执行。停止后完成的工具仍可保存真实回执，但旧请求不能再追加活动窗口。

旧受影响会话无需专用恢复按钮或删除 checkpoint。部署代码和迁移后，授权加载健康窗口时更新退役指纹；有未配对调用则按真实回执补齐。旧大结果只从当前有效窗口归档，compact 后仍可分页读取；不会回放 checkpoint 外原始聊天。本次未连接或恢复报告中的线上会话。
