## 实现与验证结果（2026-11-18）

- `pdf_pages` 只在内存尝试空密码，分别抛出 `password_required`、`invalid_pdf`、`empty_pdf` 和 `unsupported_encryption`；本地解析及通用解析入口共用此逻辑，任务及附件返回可执行提示。异常支持 Celery JSON 往返序列化。
- PDF.js 显式使用空密码，错误按 worker 异常名称分类；零字节和零页单独处理。复用当前预览窗口、下载和关闭操作，没有新增密码收集入口。
- 合成测试覆盖普通、RC4-128/AES-128/AES-256 空密码、非空密码、损坏页流、零字节、零页和 128 页 AES-128。验证页码及 chunk 原文定位、上传对象与哈希/大小/版本、跨工作区权限、失败重试不收费、云端任务复用且仅结算一次。
- Python 3.12 下对 PDF、上传、预览、附件、任务、检索、计费及鉴权共 11 个测试文件执行回归：**126 通过，1 项既有失败**。失败为 `test_chat_attachments.py::test_compaction_treats_images_as_images_and_retains_original`，图片上下文压缩返回 `failed`。在内存加载 `git show main:backend/app/parsers.py` 和 `git show main:backend/app/chat_attachments.py` 的原版模块后，独立运行仍同样失败；未扩展本 Issue 修改压缩流程。
- 前端 `npm test`：**50 通过**；`npx tsc --noEmit` 通过；`npm run build` 重试后成功。首次构建被 Next.js 自带安全升级提醒中断，重试输出同一版本存在已知漏洞的警告；建议单独升级，未在本 PDF 修复中改动依赖。
- 真实 Chromium 在现有 `/resources` 页面完成 **1440px / 390px** 验收：普通与权限加密 PDF 均实际绘制非空文字画布并翻到第二页；密码、损坏、零字节与零页提示正确；下载成功、Escape 关闭、手机 reduced-motion 和页面无横向溢出通过，无未处理页面异常。
- 桌面及手机均实际保存需要密码 PDF 的原文件，**1,623 字节及 SHA-256 与本地存储记录一致**。截图及下载位于本地忽略目录 `output/playwright/`；可重复运行的浏览器检查位于 `frontend/tests/browser/pdf-encryption.acceptance.js`。
- 浏览器使用隔离 SQLite、合成账号和本地内存对象存储替身，鉴权、Range 和下载计量走真实接口。本机 PDF 下载拦截影响原生 PDF fetch 响应，因此只在 Playwright 中保留真实 API 响应字节并调整 Content-Type、移除 Content-Disposition；未改产品响应头。原生响应头下的浏览器全链路在本机未验证通过。
