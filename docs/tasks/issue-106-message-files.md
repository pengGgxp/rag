# #106 消息文件与真实链接交付

用户已明确要求实施本计划。基线为 main@c8a7e59，分支为 codex/issue-106-message-files。

## 目标、范围与非目标

本轮工具明确关联的文件统一在助手消息下方同级平铺，正文用工具返回的真实文件名链接指出用户所需成果。新增 get_workspace_file_link，补齐读取、修改、删除、查看图片及生图任务的文件关联，复用现有预览、下载、权限与事件持久化。

文件仅显示当前内容，不做历史快照、自动分类、置顶或评分；检查图片先存入共享工作区再读取。链接默认预览，不支持的格式提供下载。原 Issue 的 PPT 渲染环境、付费验收、工具执行机制、迁移和部署均不在本次范围。

## 验收与验证

- 指定 ID/路径的链接解析只检查对应对象，不扫描目录、不读正文、不启动云电脑、不提前扣下载额度；跨工作区、删除、越界及存储错误不可生成可用链接。
- 消息级按资源 ID 去重，保留首次顺序；流式、刷新、部分失败、停止和生图后续更新均保留真实文件。列目录不批量关联。
- 正文和消息底部共用预览入口；资源页直达、复制链接、键盘、关闭焦点恢复、无权限及最新内容正确。
- 真实页面验证 PPT、图片、PDF、文本、脚本，1440/700/390px、21 文件、长名称、错误恢复和 reduced motion。
- 执行相关后端回归、前端测试、类型检查、前后端构建及 git diff --check。真实付费模型效果未验收时明确记录。

## 组件边界

现有 ConversationActivity 只负责分段过程，不能承担整条消息文件汇总；增加消息文件组件组合已有 ResourcePreview 和 Radix Dialog，不复制预览器。文件打开使用统一 hook，负责鉴权、加载、错误及焦点恢复；列表只负责等权排列。生图进度保留现有组件，只在聊天中关闭重复文件展示。

## 实现结果

- `get_workspace_file_link` 按指定 ID/路径重新鉴权，只 HEAD 对应对象；命令新建文件按需补索引，复用已有工作区锁。返回稳定 `/resources?file=ID`，不读取正文、启动环境、扫描目录或登记下载。并发补索引保持同一资源身份。
- 工具事件只公开受控文件元数据，覆盖读、写、修改、删除、视觉读取和已保存生图结果。普通命令协议不变；列目录不变为附件，历史记录不做补扫描。
- 消息文件区按资源 ID 保持首次顺序，后续更新状态。文档/图片/脚本同样式；删除保留不可用条目，图片只打开当前内容。生图任务的进度、停止、重试保存继续复用原组件。
- 正文、文件区、资源页直达链接使用鉴权后的预览路径；不支持格式可下载原文件。入口标记由 React 稳定保留，避免 Markdown 重渲染后丢失焦点；每个文件入口独立恢复焦点。
- 提示词要求明确获取真实页面链接并在正文交付，不能把存在、读取、命令或链接成功描述成质量验收。设计系统规范同步更新。

## 限制和未验收项

- 所有模型、云电脑和对象存储供应商均为本地替身，没有真实付费调用。未验收真实模型对新提示词的遵循率、供应商延迟及真实账单。
- PPT 验证的是命令保存 → 获取真实链接 → 正文交付 → 预览限制 → 下载；未改造 PPT 在线渲染环境，也未声称空白验收文稿具备内容/版式质量。
- 历史记录仅呈现已有可靠关联；不扫描历史临时图，不提供历史图片快照。不新增数据库迁移、付费配置修改或部署步骤。
- 没有执行自动合并、关闭 Issue、线上部署或业务数据迁移/删除。#106 的原有渲染目标保留独立边界，本 PR 使用 `Refs #106`。
