# Issue #89：上游调用有限重试与退避

## 目标、范围与验收

- 目标：模型调用和沙箱图片文件读取分别处理限流、临时服务错误及网络故障；改善恢复能力且不重复 Agent 回合、已成功工具或不确定的付费操作。
- 基线：从包含 PR #88 的 `origin/main@c623aac` 创建独立 worktree，分支 `codex/issue-89-bounded-upstream-retries`。Issue 领取标签与中文范围评论已写入并核验。
- 范围：四类模型协议的同步请求、同步工具流及异步正文流；图片字节传输；现有活动事件和重启恢复；分类、预算、取消/撤权、账务与工具幂等回归。
- 不包含：切换模型/供应商、修改请求参数、重放整个 Agent、线上部署、合并/关闭 Issue、付费验收、商业价格或业务数据操作。
- 验收：429/500/503 可恢复，400/401/403 不误重试；等待尊重 Retry-After、预算及取消/撤权；部分响应/工具/用量不重放；图片重试关闭旧流且不拼接部分字节，保留原摘要/长度及格式校验；刷新和重启不重复执行。

### PR90 超时复核修复范围（2026-11-12）

用户授权在现有 PR 工作区修复正常请求被固定 30 秒重试预算截短的问题，并推送本 PR。仅调整模型同步、流式和异步 HTTP 入口的超时取值；不改变沙箱图片读取预算、重试次数、计费或工具执行。正常请求保留后台配置超时，显式任务截止时间继续限制请求；重试窗口只限制等待与下一次请求准入。使用本地 HTTP 慢响应分别验证首次成功、重试后成功、任务截止时间和原有回归，不调用真实付费接口，不合并或部署。

## 重试盘点与负责层

| 调用 | 现有行为 | 本次负责层与边界 |
| --- | --- | --- |
| Chat Completions / Responses / Anthropic / Gemini | 应用直接使用 httpx，默认传输不自动重试；Agent、计量器未设置重试 | `upstream_retries` 在单次 HTTP 调用处负责；Agent 只传入取消检查和活动回调，不重试 Agent 节点 |
| e2b 2.31 文件接口 | SDK 的共享 `get_envd_transport` 设置 `connection_retries=3`；429 转为 RateLimitException，500/503 转为无结构状态的 SandboxException | 仅图片读取临时使用线程内独立 httpx 客户端，显式 `retries=0`，由文件读取外层共享预算；恢复原 SDK 客户端，不修改其他 SDK 调用 |
| 云电脑创建、命令、预览、文件写入 | 持久化执行意图、结果核对及命令摘要去重 | 保持不自动重放；图片检查命令在字节重试之前只提交一次 |
| 生图/编辑、DeepSeek 搜索、MCP、题目工作台、支付 | 有付费或写入副作用，已有调用记录/不确定结果语义；MCP 授权不代表操作幂等 | 不接入通用自动重试，不因超时/5xx 再创建、再扣费或再执行 |
| DocMind/文档处理、索引 Celery 任务 | 提交不自动重试，文档流水线已有独立任务重试 | 保持原有负责层，未把 Agent 重试叠加到任务上 |

## 规则

- 每次调用最多 3 次尝试（包含首次），基础等待 1 秒，指数增长并采用半幅到全幅随机抖动，单次等待最多 8 秒。模型的 30 秒窗口仅限制重试等待和下一次请求准入；正常 HTTP 请求（含重试后请求）使用后台配置的超时，仅在存在显式任务截止时间时进一步收紧。沙箱图片读取仍使用原有 30 秒传输预算及环境寿命约束。
- Retry-After 支持秒数与 HTTP 日期；等待至少达到其要求。若超过单次等待上限或总剩余预算，则立即结束，不提前重试。
- 明确的 429/500/502/503/504 HTTP 拒绝响应可以重试；400/401/403、其他确定错误与未知程序异常不重试。未定义任何供应商的临时 400 特例，故 400 一律按参数/配置错误返回，不猜测或修改参数。
- 模型连接建立失败及连接池超时可重试；请求写入、读取、协议中断/超时可能已产生用量，不透明重试。收到成功响应后，无论是否已发出正文，读取、解析或上游 SSE 错误均不再重放。
- 计量器仍只围绕一次逻辑模型调用建记录；成功只计最终确认用量，失败不估造用量。已有部分用量保留，安全尝试诊断写入原 thinking diagnostic。预留与最终结算路径不变。
- 图片文件读取是只读请求，可对传输故障重试。每次新建字节缓冲，失败关闭流；重试成功仍与检查命令的原始 SHA-256 和长度核对，文件变化不作为重试理由。10 MiB、4000 万像素、完整性与多模态净化规则保持。
- 等待每 100ms 检查显式取消/当前权限，每次请求前再检查；图片读取逐块检查，并以云电脑剩余寿命进一步约束预算。调用方已存在的任务 deadline 可通过 retry_scope 传递。
- 复用持久化 tool_started/tool_result 活动，显示等待时间、尝试次数和最终结果；成功后显示“请求已恢复”，失败显示脱敏原因。服务重启将未完成活动标为中断，不恢复执行或遗留等待动画。
- 日志只增加调用种类、错误分类、次数及等待秒数，不记录 URL、凭据、请求/图片正文或 SDK 原始异常消息。

## 限制及未验收项

- 未调用真实付费模型、未创建真实云电脑或执行真实沙箱验收；真实 SDK 配合模拟 HTTP 的结果不能替代云服务实际验收。
- 当前 Windows 环境未提供专用 PostgreSQL 等 opt-in 环境；相应数据库、Linux/Docker、真实云端用例按各自条件跳过。没有迁移、价格修改或业务数据操作。
- 模型的 30 秒约束重试窗口、等待和下一次请求准入，不覆盖后台配置的正常请求超时；进行中的阻塞 I/O 仍由 httpx 分阶段超时结束，不能保证在任意传输阶段按墙钟瞬间中断。已接受模型响应无论正文、工具或用量是否已到达，都不会因失败自动重放。
- 图片读取对锁定 `e2b==2.31.0` 的私有线程局部客户端做局部替换，以禁用内部重试并取得脱敏 HTTP 状态；SDK 升级时必须保留真实 SDK 回归并复核接口。不会修改其他 SDK 操作的客户端。
- 不同供应商对失败 HTTP 请求是否收费的规则无法由本地模拟验证；本实现只沿用已确认用量，不重复预留或估造未知用量，连接后的不确定传输故障不会重试。
