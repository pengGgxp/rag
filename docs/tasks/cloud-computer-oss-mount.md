# 云电脑 OSS 挂载上线

## 目标与范围

将当前工作区资源提供给云电脑使用，按工作区隔离挂载；文件修改与新产物继续进入资源库，保留版本、容量和费用记录。包含云电脑运行服务的线上更新，不改变知识库权限，不将整个站点 Bucket 暴露给沙箱。

## 验收

- 使用两个隔离工作区验证挂载目录不可越界读取。
- 验证已有资源读取、修改、新文件、资源版本冲突及删除可见性。
- 验证挂载读取与现有下载计量之间的实际关系，不宣称尚未测得的流量。
- 验证资源持久化、环境销毁和运行费用结算。
- 备份后更新 API、Worker、Web，验证实际执行链路；不能以健康检查替代挂载验收。

## 2026-11-06 检查结果

- 线上主存储为 OSS，Bucket 为 `zhikubiao`，地域为 `cn-beijing`；沙箱现有配置地域为 `cn-hangzhou`，跨地域挂载需要实际验证。
- 本地 `AlibabaSandbox.create` 尚未设置 OSS metadata，现有实现为按需文件传入与产物同步。线上仍运行原 Docker 执行器，不能描述为云电脑挂载已部署。
- 已读取阿里官方“动态挂载 OSS”文档：通过 metadata 的 `fc.sandbox.storage.oss` 指定 `mountPoints`，包含 `bucketName`、`mountDir`、`bucketPath`、`endpoint`、`readOnly`；通过 `fc.sandbox.auth.role` 提供可由函数计算扮演的 RAM Role ARN。
- 已在不输出凭据的情况下检查用户指定配置文件，没有发现 RAM Role ARN；尚未创建或修改云端 IAM 权限。
- 现有资源对象路径包含资源标识和历史版本，不等同于可直接挂载的逻辑文件树。直接可写挂载当前对象目录会绕过版本及容量业务记录，不能覆盖原对象实现编辑。
