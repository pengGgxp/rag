# Issue #100：统一 Skill 仓库

## 目标与边界

按用户 2026-11-14 确认，以 WorkBuddy 技能页为内容结构参考，统一为 Skill 仓库。取消来源分组，提供全部、已安装、未安装筛选、搜索、卡片安装和更多操作。已安装默认阅读介绍，需要时编辑真实 SKILL.md；同名多目录先选择位置。

复用系统配色、Lucide、Tabs、Dialog、文件预览及现有导入组件。只修改扩展中的 Skill 入口和详情，MCP、侧栏、工作区文件页面不改。不新增安装记录、文件副本、同步机制或付费环境调用。

## 实现与验收

- 合并现有仓库与工作区发现列表，按精确名称关联，保留所有真实目录；损坏清单独立显示修复入口。
- 浏览、搜索、筛选、安装、详情、编辑、定位、导入、卸载形成闭环，读权限与写权限保持现有边界。
- 卸载前显示目录和递归影响，取消不改文件，多个目录不批量猜测。
- 验证同名合并、独有导入、损坏清单、安装状态及搜索；运行前端测试、类型检查、构建和 diff 检查。
- 使用现有隔离 Docker 临时工作区实际测试，保存并逐张检查 1440/700/390px 截图、菜单焦点、长名称、空搜索、错误与只读状态。更新 design-qa.md 和交付记录，不连接生产或收费模型。

## 实施结果

- 新增业务组件 `SkillCatalogView` 组合既有 Tabs、Dialog、加载、导入与预览，现有扩展列表不适合卡片安装流程，因此仅将 Skill 内容独立为业务组件；没有新增基础组件或依赖。`query/status/returnTo/filter` 负责路由状态，菜单、位置选择及安装反馈在组件内部管理。菜单支持方向键、Home/End、Enter、Escape及焦点恢复；手机操作至少44px，无额外动效。
- 按精确名称聚合源包与真实发现结果，多个安装目录保留独立路径。缺少名称的损坏清单按文件ID保留；简介无效仍按已解析名称关联。卡片已安装数量按Skill名称分组计数，多个目录另显示位置数量。
- 已安装详情默认阅读工作区当前正文，按需编辑；卸载按当前真实目录预检，显示文件/目录影响并明确确认。已安装且有关联源包时，更多菜单可下载仓库包；这是管理员原包，非用户修改副本的导出。
- 本轮没有后端、数据模型、模型提示词或权限变更，原安装/发现/文件API和A方案并发边界继续适用。
