# 测试分支与手动镜像发布

## 目标和边界

PR 先合并到 `test`，再由开发者在本地显式执行镜像构建和推送，
最后更新 fsl1 测试环境。当前不新增、触发或配置 GitHub Actions CD。
为避免测试路径消耗 Actions 额度，现有 CI 跳过目标为 `test` 的 PR，
现有云电脑镜像工作流也跳过 `test` 的推送；检查在本地执行。
不改动正式环境发布流程、不处理本轮暂停的模型异常，也不启用题库。

## 范围

- 为测试环境提供可复现的 API、预览 Worker 和 Web 构建。
- 本地发布入口只接受已推送的干净 `test` 提交，记录提交和镜像 digest。
- 服务器使用已有 `zhiku-private-test` 项目、配置、数据库和缓存卷；
  只拉镜像，不在服务器构建。
- 更新前备份数据库；迁移失败不启动新应用；成功后验证 API、
  Worker、预览、Web、Alembic 和提交版本。

## 验收与验证

- 发布入口拒绝错误分支、脏工作区、未推送提交和无效镜像标识。
- 部署入口拒绝缺失配置或已有数据卷，避免启动空数据库。
- 测试覆盖构建来源、镜像记录、失败中止、备份和健康检查。
- 使用 Compose 渲染检查配置；本地隔离容器验证部署流程。
- 远端验收仍需 fsl1 SSH 恢复和本地 SWR 登录可用。
  未实际执行镜像推送及服务器更新前，不把路径描述为已打通。
