# 文档提及与扩展补全（Issue #73）

## 目标与边界

用户在对话输入 `@` 选择当前会话知识库中的可用文档，显示文件名与链接样式；请求另外提交 ID，由服务端解析文件名与知识库归属。提及按单轮保存，刷新恢复，重试复用原轮次。

提及不会强制整轮只查这些文档。模型获得本轮文档清单，可自行回答、正常搜索知识库，或显式传入 `search_knowledge_base.document_ids` 搜索指定文档。未提及 ID 不允许作为此工具参数；权限、删除、处理状态与活动版本过滤继续生效。不修改价格、默认模型或引用规则。

## 实现边界

- `DocumentMentionMenu` 负责文档候选、过滤、异步加载及选择；复用扩展补全的样式与输入键盘约定，不引入新 UI 库。文档与扩展数据来源、选择结果不同，因此保持独立业务组件。
- 输入区继续使用 textarea，样式叠层只负责文件名标记；字体、字重、行高、换行、宽度及滚动对齐。删除提及后移除对应 ID，失败保留草稿。
- `/` 使用紧凑扩展补全菜单，与 `@` 互斥；方向键、Enter、Tab、Escape 可用，输入法组合期间不选择或发送。
- Alembic `0044_chat_document_mentions` 为消息新增 JSON 列，历史消息默认为空列表。按部署流程先升级数据库，再启动 API；无历史内容回填。
