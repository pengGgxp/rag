# 知识提及与扩展补全（Issue #73、#86）

## 目标与边界

对话无需固定绑定知识库。用户在输入区通过 `@` 选择当前工作区内有权访问的知识库、可用文档或资源文件；补全按类型分组、随输入筛选，文档显示所属库，资源文件显示相对路径以区分同名资料。请求另外提交 ID，由服务端解析名称与归属。三类合计最多 8 项，提及按单轮保存，刷新恢复；重试保留历史显示，并排除当前已失权或不可用的提及。

资源引用以 `@资源/相对路径` 显示，请求提交 `resource_ids`，消息保存 `resource_mentions` 定位快照。目录仅列元数据，发送前及 Worker 开始时重新检查当前工作区成员与资源可用性，不预读正文、不转换为附件，也不是知识库证据。仅选择或发送不启动云电脑、不产生云电脑费用；实际读取或修改按现有工具权限、启动及计费规则执行。资源文件当前采用工作区共享语义；历史标记保留当时名称，重试向 Agent 提供当前可用文件的最新元数据。

提及是优先线索，不是整轮硬检索范围。模型可按需调用 `discover_knowledge_bases` 发现授权资料，再用返回的文档 ID 或本轮提及的文档 ID 调用 `search_knowledge_base.document_ids` 定向检索，无需用户先 `@`。服务端每次核对当前工作区、知识库权限及归档状态、文档归属、READY 和活动版本；发现结果不是权限凭据，撤权或失效后不得继续检索。不修改价格、默认模型或引用规则。

## 实现边界

- 输入框占位提示为“输入消息，@ 引用资料，/ 命令与扩展”，沿用原有浅灰样式；输入后自然隐藏，不增加常驻说明或教学弹窗。
- `DocumentMentionMenu` 负责知识库、文档与资源文件候选、分组、过滤、异步加载及选择；复用扩展补全的样式与输入键盘约定，不引入新 UI 库。资料与扩展的数据来源、选择结果不同，因此保持独立业务组件。
- 输入区继续使用 textarea，样式叠层只负责文件名标记；字体、字重、行高、换行、宽度及滚动对齐。删除提及后移除对应 ID，失败保留草稿。
- `/` 使用紧凑扩展补全菜单，与 `@` 互斥；方向键、Enter、Tab、Escape 可用，输入法组合期间不选择或发送。
- Alembic `0044_chat_document_mentions` 为消息新增 JSON 列，历史消息默认为空列表。按部署流程先升级数据库，再启动 API；无历史内容回填。
- Alembic `0064_knowledge_mentions` 为消息新增知识库提及列表，默认 `[]`；修订号符合现有 PostgreSQL 版本列的 32 字符长度限制。隔离迁移验收使用 `AUTH_TEST_DATABASE_URL` 运行 `tests/test_knowledge_mentions_migration.py`，核对升级、重复升级、回退再升级、消息和账务快照保留。
- Alembic `0065_resource_mentions` 为消息新增资源提及列表，历史和新消息默认 `[]`；同一隔离迁移回归验证资源快照写入及既有数据保留。
