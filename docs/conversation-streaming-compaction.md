## 目标与边界

实现真实上游流式、有序工具反馈、可恢复的上下文整理。保留请求级模型选择、
RAG 权限与引用、原始聊天、现有价格及倍率；不启用 Issue #36，不增加依赖或 Worker。
整理使用本次模型并按实际模型用量计费，不另收次数费。

## 交付顺序

1. 独立本地可交互样稿，确认桌面与手机视觉；样稿数据不部署到正式功能。
2. 真实流式与调用记录：正文、工具碎片、最终 usage 共用入口；取消与异常保留已确认消费。
3. 对话视觉与活动轨迹：有序正文块、紧凑状态、回答详情、滚动跟随。
4. 上下文整理：预算、模型容量、检查点、自动与手动接口、历史授权回查。
5. 后端、PostgreSQL、构建、浏览器及受控真实调用验证后，再备份部署 API/Web 和新增结构。

## 视觉确认

- 复用 Dialog 的 anchor 模式、Tooltip、Motion、Lucide 与现有选择器。
- 活动行以状态图标、用途和安全摘要表达，不显示原始参数或工具正文。
- 每次工具调用在实际发生的位置插入独立活动行，与正文交错；完成后原位置保留自然语言摘要。
  不集中放在消息顶部，不合并隐藏后续调用；主动展开后不自动折叠。
- 回答操作保持轻量，模型和请求思考快照只在回答详情展示。
- 上下文入口使用低干扰容量图标，展开后显示估算、输出预留、整理状态与费用说明。
- 未配置容量不显示百分比；手动整理需要明确计费确认，无内容时禁用。
- 手机操作至少 44px，无横向溢出，支持 Escape、焦点返回和 reduced motion。

## 服务端约束

- 稳定 SSE ID/序号及有序消息块；保留纯文本 content 和旧消息显示。
- 工具参数完整且通过权限、格式验证后执行；停止不启动后续调用或重放副作用。
- 每轮完整输入预算含规则、历史、工具、Skill、结果及协议开销。
- 可用输入为容量减输出预留和容量 5% 余量；达到其 75% 尝试整理。
- 保留最近两个完整用户轮次与当前轮次；不拆工具组，不把摘要升级为指令或检索证据。
- 每边界最多一次整理，失败保留原上下文；超硬预算返回可恢复错误。
- 检查点保存覆盖范围、来源版本、模型和估算；权限或来源变更时失效。
- GET /conversations/{id}/context；POST /conversations/{id}/compact 返回 SSE，不伪造聊天回答。
- 自动整理并入原请求，手动整理独立结算；两条现有结算路径公式和开关保持不变。
- 新结构仅新增；历史消息、消费和余额不回填、不重算。
